# 访谈报告 V2：解析异常与稳定错误码

> 状态：持续更新至批次 6B2。错误码属于接口合同，不得用模型自由文本替代；当前不定义病毒扫描告警。

## 分类

- `blocking`：不能创建正式项目或不能进入下一阶段。
- `confirmation_required`：保留已完成物理解析，但必须人工确认。
- `warning`：允许继续，且不得把不确定内容用于正式报告主张。
- `partial_failure`：保留成功单元，只重试失败范围。

## 分析、报告与恢复

批次 6B1 开放 `POST /api/v1/interview-projects/{project_id}/reruns` 的 `from_stage=report_section` 单章节重生成。请求必须同时固定 `base_report_version_id`、`section_id`、`base_section_revision` 与 `Idempotency-Key`；只能覆盖一个未锁定章节，并派生新的不可变 draft。其余章节、主张、审计问题、人工锁定内容、旧批准版与既有 DOCX 均保持不变。同一用户和项目下相同幂等键和相同输入复用已完成结果；相同键绑定不同输入时拒绝；模型或保存失败不得推进报告头。

批次 6B2 在同一接口增加 `from_stage=analysis_module`，保持 6B1 请求兼容。模块请求固定 `base_analysis_run_id` 和单个 `module_id`，不接受玩家范围、模块数组、重写指令或强制覆盖：

```json
{
  "from_stage": "analysis_module",
  "base_analysis_run_id": "analysis_0123456789abcdef0123456789abcdef",
  "module_id": "module_0123456789abcdef0123456789abcdef",
  "preserve_manual_report_edits": true,
  "reuse_unchanged_artifacts": true,
  "force": false
}
```

- 仅允许基于已完成且上游未变化的当前分析重跑一个模块。冻结基础产物哈希、结构/证据/覆盖/档案版本、目标模块输入、Prompt 快照及模型配置；若准备或提交时发现输入变化，拒绝推进分析头。
- 只对目标模块执行分析调用。其他模块复用研究发现、来源、限制和统计口径；版本相关的 `StatFact` 标识及 `analysis_run_id` 重新绑定到新分析版本，数值与证据不变。零发现模块仍可被选择和重跑。
- 新分析是不可变版本。已有报告、人工锁定内容、批准记录和 DOCX 不被改写；报告沿用现有依赖检查提示过期，不自动级联生成报告。
- 模块与章节共用用户/项目幂等键命名空间。相同键跨类型、改模块、改基线或改 Prompt/模型配置均返回 `RERUN_IDEMPOTENCY_CONFLICT`；相同活动请求返回 `RERUN_IN_PROGRESS`。
- 失败和取消释放未提交占位。结果必须存在于已提交分析历史中才能复用；仅写入版本文件但未提交分析头的残留文件不可读取或复用。分析头已提交但完成标记写入失败时，同键重试恢复原结果，不再次调用模型。
- 响应包含 `analysis_run_id`、`analysis_version_number`、`is_current_version` 和 `rerun`。历史结果重放不会改回当前分析头，且会如实返回非当前/过期状态；前端刷新真实当前版本。
- 本批不提供服务重启后继续执行未完成模型任务、后台任务/SSE、跨玩家或模块的自动增量失效重算。存储故障后的恢复只覆盖已提交结果识别。

批次 6B3 在同一接口增加 `from_stage=participant_dossier`，只用于当前有效档案的单玩家重跑；首次生成和上游已变化后的“按最新证据重新生成”仍使用 `dossiers:regenerate`：

```json
{
  "from_stage": "participant_dossier",
  "participant_id": "participant_0123456789abcdef0123456789abcdef",
  "base_dossier_version_id": "dossier_0123456789abcdef0123456789abcdef",
  "preserve_manual_report_edits": true,
  "reuse_unchanged_artifacts": true,
  "force": false
}
```

- 请求固定一个玩家和当前档案基线，不接受数组、改写指令或强制覆盖。服务冻结目标玩家有效证据、档案基线哈希、结构/证据/边界/覆盖来源、两套 Prompt 快照和模型配置，并只执行属性抽取与档案生成两次模型阶段。
- 新结果以不可变 `generated` 版本提交，不继承旧档案批准；其他玩家档案、人工修正、分析、报告、锁定正文、批准记录和 DOCX 不改写。既有依赖检查负责标记下游过期，不自动级联。
- 玩家档案、模块分析和报告章节共享用户/项目级幂等键命名空间。同键改玩家、基线、Prompt、模型配置或重跑类型返回 `RERUN_IDEMPOTENCY_CONFLICT`；活动请求返回 `RERUN_IN_PROGRESS`。
- 提交在同一项目锁内校验档案头、基线摘要和当前上游来源。模型无效、失败、取消或提交冲突不会推进档案头，并释放未提交占位。
- 只有已进入档案 history 且摘要完整的结果可以重放；孤立版本文件不得恢复为成功。档案头已提交但完成标记写入失败时，同键重试恢复已提交结果，不再次调用模型。
- 历史结果重放不会把当前档案头倒退；响应返回 `is_current_version`，前端随后刷新真实当前玩家版本。
- 本批不提供玩家级自动增量复用、后台 Job/SSE、服务重启后继续未完成模型任务、运营后台、真实模型试点或部署。

## 统一错误体要求

V2 路由和 service 自身产生的业务错误至少返回：

```json
{
  "error": {
    "code": "PARTICIPANT_MAPPING_AMBIGUOUS",
    "message": "同组玩家列无法可靠对应，请确认玩家关系。",
    "retryable": false,
    "suggested_action": "open_group_mapping",
    "context": {},
    "trace_id": "trace_01"
  }
}
```

`context` 只包含定位所需 ID、Sheet/列坐标和计数，不记录玩家原文。

平台统一登录/权限中间件仍沿用现有 HTTP 错误语义，不属于本文件的 V2 业务错误体。部署配置为 `INTERVIEW_V2_ENABLED=false` 时，`app/main.py` 不注册 V2 路由，对外表现为端点不存在；`INTERVIEW_V2_DISABLED` 仅是路由被独立挂载时的防御性保护。
