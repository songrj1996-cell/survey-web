# LLM 管线工程门禁

本文用于所有依赖模型执行压缩、筛选、去重、归并或逐轮收敛的流程。仓库规则、运行时代码
和自动化测试是事实来源；Codex memory 只能提醒，不能替代这些门禁。

## 契约先行

修改流程前先写一张契约表，至少包含：输入、输出、是否允许遗漏输入、数量上下限、有效空结果、
成功条件、失败降级、阶段预算和诊断字段。如果新旧约束不可同时成立，必须使用不同的 prompt、
validator 和输出结构；只允许复用底层 HTTP、JSON 解析和通用重试能力。

当前问卷开放题的两个阶段不得混用：

| 阶段 | 输入处置 | 数量规则 | 成功条件 |
|---|---|---|---|
| 逐题主题合并 | 每个候选恰好进入一个最终主题 | 不设主题数量目标 | 候选完整覆盖、无重复、引用可追溯 |
| 跨题共同观点筛选 | 每个候选明确标为选中或排除 | 最多 36 条共同观点 | 每条至少覆盖两个 scope；有效空结果必须显式声明并排除全部候选 |

跨题阶段使用 `viewpoints`，逐题阶段使用 `themes`。字段不同是防止错误复用 validator 的边界，
不得为了“统一结构”再次合并。

## 时间与无进展保护

- 单次请求超时不等于阶段预算。跨题筛选和原文回查共享一个绝对 deadline，默认 300 秒。
- 启动前计算计划逻辑调用数；结束后同时记录已完成逻辑调用数和真实上游 HTTP 尝试数。
- 返回旧协议、超过数量上限、未跨题、候选未完整处置或输出截断，都属于不收敛。
- 不收敛结果只允许在同一总预算内做一次结构修正；仍失败就透明降级，禁止原样进入下一轮。
- 超时后的不完整跨题统计不得进入 Writer；逐题主题和原文继续保留。

## 必须保存的诊断

- 契约版本、状态、停止原因、阶段预算与实际耗时。
- 输入候选数、选中候选数、排除候选数、最终观点数和保留率。
- 计划/已完成逻辑调用数、分类批次数、分类兜底数。
- 每次逻辑调用的模型、fallback、修复、输出长度、timeout、finish reason 和耗时。
- `report_llm_usage.phases.synthesis` 中的真实上游尝试数与 token 使用。
- Writer 最终是否收到观点目录，以及最终报告是否正确引用观点。

## 真实规模回放

高风险改动合入 `main` 前，必须用经过隐私审查的脱敏样本和真实模型运行回放。样本应保留真实
数量级、题目分布和重复/独有语义结构，不得包含玩家 ID、联系方式或未经批准的原文。

跨题门禁的基准样本包含 173 个候选。验收要求：

1. 只执行一次跨题筛选，不进行多层重复归并。
2. 整个跨题阶段不超过 300 秒。
3. 产生 1–36 条有效共同观点，每条至少覆盖两个 scope；或在确无共同观点时完整返回有效空结果。
4. 没有未知、重复或静默遗漏的候选 ID，没有输出截断。
5. 逐题主题和原文不变，Writer 上下文隔离及 token 优化不回退。
6. 回放结果必须记录目标提交、模型、调用数、token、耗时、fallback、停止原因和最终产出。

只有 mock/单元测试通过时结论仍为 NO-GO。真实模型回放满足全部条件后，才能给出 GO。

## 提交与回退

至少按以下边界拆分：

1. 规则、契约文档与回放规范。
2. prompt、validator、输出协议及其契约测试。
3. 算法、阶段预算、熔断和诊断。
4. 脱敏回放样本、回放证据和默认策略切换。

每个提交都要能独立验证和独立回退。关闭跨题能力时应透明退回逐题主题与原文写作，不能退回
已知会无界耗时的旧分层算法。
