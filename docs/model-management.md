# 后台模型管理

本功能覆盖 38 个业务环节。管理员可在“设置 → 模型管理”维护模型目录和业务配置；普通用户继续从原业务入口使用。

## 管理员操作

1. 在“模型目录”登记服务接受的模型标识、支持的推理程度、上下文容量和最大输出。能力未核实时保留“未核实”；模型出现在列表中不代表当前用户有调用权限，也不代表该模型已通过质量验收。
2. 在“业务配置”选择业务和环节，设置主模型及它的推理程度。添加备用模型后调整顺序，每个备用分别设置推理程度和输出长度。修改未核实模型的调用设置前，须填写实际限制和核实依据。
3. 高级设置中的等待时间及真实请求上限可留空以沿用原规则。真实请求上限包含重试、协议兼容及备用请求；原业务更严格的限制仍可能先结束本次尝试。请求上限只有 1 次时不能配置备用模型。新增能力不会自动给原先的单请求流程开启额外调用。
4. 点击“预览发布”，核对改动及检查结果后发布。草稿不生效，刷新或离开前会提醒；检查和发布本身不调用模型。
5. 多名管理员同时修改时，版本冲突会保留本页草稿。加载最新配置，逐项核对冲突后重新检查。不要反复点击发布。
6. 在“版本历史”选择恢复，得到历史配置的草稿；再次核对后发布为新版本，保留原历史记录。

## 配置来源和生效边界

- `.env` 和 `app/core/config.py` 提供模型服务地址、密钥规则、路径及初始默认设置。后台只保存模型目录、业务参数和版本历史，不改写环境文件，不存密钥。
- 配置文件位置由 `LLM_MODEL_SETTINGS_FILE` 指定；默认在 `DATA_DIR` 内。读取页面不创建文件，首次发布才写入。真实数据目录的初始化、备份、迁移或恢复需单独授权，本次开发和离线验收均未操作真实数据。
- 未发布时使用环境默认 v0；发布后新任务冻结发布版本。进行中的任务、内部并发批次和备用尝试继续使用启动时的快照。
- 报告补全、访谈恢复、标注缺项补跑和后台标注续跑沿用原任务或原阶段快照。主动完整重新生成是新任务，可以使用新版本；复用旧材料和未重写部分不代表它们也重新经过新模型处理。
- 原任务没有保存快照且当前已有发布版本时，恢复会停止并提示完整重新生成。不要手工给旧报告补填当前配置版本。旧报告仍可查看，历史结果不批量迁移。
- 配置损坏、快照校验失败或版本冲突时明确报错，不清空配置、不静默改用另一套模型。请先保留现场并核对备份；恢复配置文件不包含恢复业务输入、报告或模型权限。

## 兼容和容量限制

- 每个候选模型使用自己的参数。显式推理程度在支持的协议中送出；不支持该参数的协议分支不会被当作已经执行了所选推理程度。未发布的默认路径保留原调用约定。
- 模型目录的能力由管理员核实，保存成功不证明上游服务实际支持参数、账号有权限或报告质量合格。认证或访问被拒时检查个人模型凭据及服务授权；不把某个管理员的结果当作所有用户均可用。
- 最大输出和上下文容量不同。输出设置超过目录限制不能发布；调用前也检查输出限制。管理配置中的各候选按完整原消息、各自上下文和输出预留独立估算；写作切换候选时同步更新容量进度和检查点。容量估算只作提示，未知或超限也按原规则继续请求，不删减材料、不自动拆批，不保证请求能完成。图片及工具消息等尚不能可靠估算的输入显示未知。
- 输出截断不能当作完整结果。提高推理、输出长度或请求上限，以及实际触发备用，都可能增加等待和费用。降低输出或换用较弱模型可能影响准确性、完整性和引用可靠性。

## 日志与用量

- 模型请求元数据包括配置版本、业务环节、请求模型、服务返回的模型标识（有则记录）、实际送出的推理参数、输出上限、协议、真实尝试次数和备用使用情况。
- 业务手工轮换候选时，结合相同版本的冻结配置识别备用，不把当前最新版本套到旧任务。无配置版本或环节证据时保持未知。
- 用量接口的任务记录增加 `model_settings_used`。每项按版本、环节、模型、参数和协议聚合真实尝试、成功、失败及接口耗时；重复终止事件不重复计数。旧记录缺字段时返回空列表，不补写旧数据。各请求接口耗时之和不等于并发任务的墙钟总耗时。
- 原有 Token 汇总仍只累计已返回的部分；`usage_missing_call_count` 非零表示存在未知或不完整用量。未知不是零消耗，不能据此断言免费，也不把 Token 数换算成未经核实的金额。
- 终端日志保留中文业务阶段、失败、重试、协议切换和备用使用，正常批次成功提示按配置组合去重。请求成功不代表报告已经生成或保存成功。认证、限流、超时等按结构化证据说明，不猜测供应商原因。
- 备用模型容量未知、接近上限或超限时，日志明确标为本地预估，记录数值和对应输出预留，不声称服务已经拒绝。相同容量风险组合去重；预估值不是计费用量。
- 不把问卷、报告正文、原始错误体、请求头、模型密钥或登录资料写入新增元数据和日志。操作人沿用姓名展示，不展示邮箱或账号标识。

## 离线验收与上线边界

隔离设置 `DATA_DIR` 后再导入应用模块；不启动真实应用清理入口，不访问真实模型、飞书或生产数据。使用合成材料、模拟 HTTP/流式响应及实际配置接口，检查：

- 管理员权限、目录及参数检查、并发发布、冲突保留和历史恢复。
- 38 个环节的参数路由、备用的独立参数、协议兼容、请求总上限、超时和取消。
- 运行中发布、并发隔离、报告版本、检查点、后台标注和缺项恢复。
- 日志中文信息、带时区时间、姓名展示、敏感信息保护、用量不完整及旧记录读取。
- 后端分层、Python/JavaScript 语法、浏览器草稿和发布流程、桌面与窄屏布局。

离线验证和本地开销测量只能证明接线、保护条件及所测环境的表现，不能证明真实模型的报告质量、总耗时、权限或费用。高风险 LLM 流程在完成另行授权的真实规模、真实模型回放前，合入及上线结论为 **NO-GO**。提交、合并、推送、部署和真实模型回放分别授权。

回退应按独立提交核对影响后执行。仅回退代码不会自动撤销已保存的后台配置或改写历史任务快照；配置恢复应先预览、后发布新版本。不得以代码回退为由清理真实数据或配置文件。
