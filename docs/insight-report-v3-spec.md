## 1. 目标与边界

现有 `report_mode == "insight"` 的正文生成存在三类问题：

1. 主题提取、合并、逐条分类、跨题归纳和分章写作调用多且整体耗时长。
2. 分批主题流程中的局部失败可能阻断整份报告。
3. 报告按问卷 Part 切章并重复展示统一证据表，不符合目标报告的研究主线。

V3 的目标是让证据校验成本与报告实际引用量相关，而不是与全部回答数和全部主题数相乘。
时间是需要记录和优化的指标，不是中止报告的理由。

阶段一的质量定位是：

> 证据绑定 + 防明显夸大。

阶段一不能保证“无 AI 杜撰”。它能确定性保证引用身份存在、归属当前题、频次档位满足代码
下界，并阻止模型直接输出原文；`support_count` 仍是模型对唯一玩家数的估计，必须通过真实材料
抽查评估偏差。语义曲解由阶段三审校继续处理。

## 2. 不可违反的红线

### 2.1 模型不得输出原文

- 模型输出契约中不得有 `quote`、`text`、`excerpt`、`snippet`、`original`、
  `source_text`、`translation` 等承载原文的字段。
- 模型只输出当前一次调用内的短 ID。
- 原文、全局来源 ID 和玩家身份均由代码本地管理。
- 禁止让模型复制长 ID 或原文后再做字符串匹配。

### 2.2 局部失败不得阻断其他题

- 单题失败只降级该题。
- 单章失败只影响该章。
- 审校未解决的问题标注后交付，不丢弃报告。
- 已完成题必须增量保存，后续题失败不能使其作废。

### 2.3 前四步旧行为保持不变

上传、列识别、方案规划、统计的现有生产调用路径和默认输出保持不变。阶段一 CLI 必须直接调用
这些现有 service 函数，不实现第二套列识别、规划或统计。

当前 V3 不修改 `survey_stats.py`。来源身份使用完整文件哈希、冻结方案指纹、原始开放题列表的
确定性顺序和玩家键生成。若未来必须增加行号，只允许新增 V3 显式开启的 keyword-only 来源
元数据；默认调用行为和输出必须由深度相等测试守住。

### 2.4 真实数据隔离

- 主工作树 `data/` 不得读写。
- 自动 CLI 在显式 `runtime-root` 下创建独立 `data/` 与 session。
- 人工验收可在 V3 工作树自己的隔离 session 中完成。
- 验证证据不得重复写出原始回答；原文只留在隔离 session 来源注册表。

## 3. 阶段一跨阶段契约

### 3.1 双层来源 ID

模型只看到并输出现有 `report_engine._response_ref` 生成的短 ID：`r0001`、`r0002`……

代码为每列完整开放题列表构造全局来源 ID：

```text
ir3v1-{file16}-c{column_index}-i{source_index}-p{respondent12}
```

- `file16`：文件 SHA-256 前 16 位。
- `column_index`：原始零基列号。
- `source_index`：该列完整 `open_text` 列表中的一基确定性位置，不是批次位置。
- `respondent12`：文件哈希与 `respondent_key` 联合 SHA-256 的前 12 位。
- 完整文件哈希、plan 指纹和来源注册表指纹保存在 `source_binding` 中。

全局 ID 不进入模型上下文。代码现场维护 `短 ID -> 一个或多个全局来源 ID` 映射，校验模型
短 ID 后再展开并写入 finding。阶段二只按来源注册表精确回填，不解析 ID 猜测原文。

### 3.2 玩家级预合并

同一题、同一 scope 内，代码先按 `respondent_key` 合并同一玩家的多条文本，再分配一个短 ID。
因此模型看到的每个短 ID 代表一名玩家。玩家哈希和明文身份均不进入模型上下文。

非开放题在 scope 选择阶段直接排除，不进入 `questions`。只有开放题没有有效回答时才使用
`status = "skipped"`。

### 3.3 `support_count` 口径

- `N` 是当前题和 scope 内有效回答的唯一玩家数。
- `support_count` 是模型估计的支持该 finding 的唯一玩家数。
- 代表样本最小数也按唯一玩家计算。
- 比例下界统一向上取整。
- 必须满足：`唯一代表玩家数 <= support_count <= N`。

批准的档位如下：

| 档位词 | support_count 下界 | 唯一代表玩家最小数 |
|---|---:|---:|
| 绝大多数 / 普遍 | `ceil(N × 50%)` | 5 |
| 大量 / 很多 | `max(6, ceil(N × 20%))` | 5 |
| 不少 / 多名 | 5 | 3 |
| 部分 | 3 | 3 |
| 少数 / 个别 | 2 | 2 |
| 有玩家 / 有受访者 | 1 | 1 |

不同语义档位的可用 `support_count` 下界必须严格递增。极小样本下整数档位可能碰撞；代码按
“防夸大”的保守原则保留较弱表述，并把下界相等或倒置的更强档位标为“本题不可用”，模型
校验也必须拒绝该档位。例如 N=10 时，“绝大多数/普遍”不可用，不能靠模型自报数字伪造档位
差异。

跨题 `support_count` 禁止相加。跨题 finding 不生成总人数、比例或全局频次档位，只允许使用固定
口径“多道题均有提及”。如需精确跨题人数，必须另做逐条判定。

### 3.4 降级结构

阶段一产物版本为 `insight-findings-v1`。每题结构至少包含：

```json
{
  "question_key": "12",
  "scope_key": "12",
  "column_indexes": [12],
  "status": "complete | degraded | skipped",
  "respondent_count": 95,
  "findings": [],
  "degraded_source_ids": [],
  "failure": null,
  "diagnostics": {}
}
```

- `complete`：产出并通过契约校验。
- `degraded`：不保留未通过校验的 finding；`degraded_source_ids` 保存该题全部来源 ID。
- `skipped`：开放题没有有效回答。
- 阶段二对降级题按 ID 回填全部原文；阶段一不抽样、不截断、不静默丢弃。
- 指纹不符或 ID 不可解析时只阻断该题，并显式告警。

## 4. 阶段一执行规则

- 每道开放题一次逻辑调用，模型复用 `LLM_THEME_EXTRACT_*` 配置。
- 逐题并发默认 2，可在隔离试验中测 2、4、6。
- 每题首次调用后最多重试 2 次。
- 单次请求继续使用现有调用超时、协议切换、模型 fallback 和 JSON 修复。
- 输入超过保护阈值时该题降级，不把截断内容交给模型。
- 整个阶段默认超过 20 分钟只告警一次并继续，不设置生产硬截止。
- 仅隔离 CLI 显式传入 `--hard-timeout-seconds` 时允许试验硬截止；已完成题仍保存。

必须记录：

- 计划和实际逻辑调用数；
- 真实上游 HTTP 尝试数；
- 每题输入长度、模型、修复、错误、耗时和停止原因；
- token 用量及其是否完整；
- complete / degraded / skipped 数量；
- 阶段总耗时、并发和是否告警。

## 5. 阶段一 CLI

`scripts/replay_insight_report_v3_findings.py` 支持两条路径：

1. 自动路径：读取 XLSX，直接调用现有上传、列识别、列确认、方案规划、方案确认和统计 service，
   自动确认模型结果，然后运行阶段一。
2. 人工路径：复用用户在工作树服务中手动完成前四步的 session，仅运行阶段一。

两条路径必须写入同一个 `sess["insight_v3_findings"]` schema。每完成一题立即更新 session。
CLI 必须显式传 `--real` 才能调用真实模型；真实配置可用 `--env-file` 只读导入 `LLM_*`。

## 6. 后续阶段边界

阶段二负责：章节规划、按分析维度分章写作、固定背景与样本概况、核心发现汇总、统计附录、
正式 `survey_service` 接入、引擎开关和版本绑定。

阶段三负责：正文语义审校、未解决问题标注交付和频次门禁持续发现。追问时按需计算精确人数
不在本轮阶段三范围内，须另行设计与授权。

### 6.1 客观题统计必须走附录路径

V3 正文不生成旧引擎使用的 `## Part X` 标题，因此 V3 路径禁止调用
`stats_presentation.inject_qualitative_stats`。该函数按 Part 标题定位插入点；找不到标题时会跳过，
可能在不报错的情况下使逐题客观题统计完全缺失。

V3 必须复用后段已有的 `render_stats_appendix`，把逐题客观题统计作为附录追加到正文之后。
样本概况章只呈现总体样本结构和经筛选的画像表，不重复附录中的逐题统计。

### 6.2 引擎开关与版本绑定

- 新增 `INSIGHT_REPORT_V3_ENABLED`，默认值为 `True`。
- V3 版本快照必须保存 `report_engine = "insight_v3"`。
- 新生成的 `insight` 模式报告仅在开关启用时进入 V3；`quick` 与 `statistics` 始终保持原引擎。
- 缺少显式 `report_mode` / `report_engine` 的旧式 session 继续按 `legacy` 处理，不得因默认开关开启
  而在下一次写入时被静默迁移到 V3；只有明确保存 `report_mode = "insight"` 的新会话由开关接管。
- 历史报告重跑必须按版本快照中保存的 `report_engine` 选择引擎，机制复用
  `resolve_report_mode` / `report_mode` 的版本绑定方式。
- 关闭开关后，已保存为 `insight_v3` 的版本不得静默退回旧引擎；无法按原引擎重跑时必须明确失败并说明原因。

### 6.3 局部重做的预期降级

V3 snapshot 不保存 `analysis_artifacts`，因此现有局部重做能力会自动判定为不可用。这是阶段二的
预期降级，不得导致报告生成或历史查看失败。V3 必须提供明确的不可用原因，例如：

> 新版报告暂不支持局部重做，请整份重新生成。

禁止让 V3 落入默认空 `reason`。阶段二不实现 V3 局部重做，也不得伪造旧引擎所需的分析产物。

### 6.4 样本概况章体积上限

样本概况章正文最多 500 字、不设字数下限，最多 2—3 张相关表，不为达到字数填充系统说明。代码从完整确定性统计目录组装时，
只允许选取单维画像分布，以及少量与 `analysis_focus` 直接相关的表；其余统计表进入统计附录，
或不进入报告。不得把全部统计表复制到正文。

表格选择、数量限制和正文长度要求由代码确定性约束；模型不得自行扩大表格集合。样本概况章的
总体统计来自确定性 stats，不受观点级画像数字禁令限制，但不得与逐题统计附录重复。

概况内同一画像分布只展示一次：同名、相同数据行且其它口径元数据一致的单维表，可忽略
“取值／选项”表头与 Markdown 空格、对齐标记的显示差异去重；不得仅凭标题相同去重。
没有画像分布作为依据的不同 Part 表不合并，原始统计与完整附录均不修改。

### 6.5 SSE 进度阶段

V3 使用固定四阶段进度协议，`phase_total = 4`：

| phase | phase_index | 含义 |
|---|---:|---|
| `themes` | 1 | 阶段一逐题 findings 提炼；继续提供 `item_total` / `item_index` |
| `writing` | 2 | 章节规划、画像按需验证与正文写作 |
| `audit` | 3 | 阶段三语义审校；必须区分通过、已修复、待人工复核、未完整执行和无可审校内容 |
| `finalize` | 4 | 复用现有后段完成统计附录、校验、保存和完成事件 |

`themes` 名称不得另造，以便复用前端现有逐项进度条。`finalize` 必须由复用的后段发出，V3
正文生成器不得重复发送最终完成事件。

### 6.6 snapshot 字段与接入红线

V3 版本 snapshot 按以下规则写入：

- `analyst_app = "insight_v3"`；
- `viewpoint_diagnostics` 保存新引擎自己的诊断，至少包含逐题成功/降级状态和各章重试次数；
- 不写 `analysis_artifacts`，以触发 6.3 的明确局部重做降级；
- `comparison_validation` 保持现有结构和行为，继续对最终 `full_report` 做确定性校验。

正式接入只允许在 `_full_report_stream` 的中段正文生成位置增加 V3 分支。其前段的版本解析、
生成锁、权限校验、历史重跑和统计准备必须保持逐行不变；后段继续负责附录、确定性校验、版本
保存和 `finalize`。交付时必须用定向 `git diff` 证明前段没有改动。

### 6.7 三层画像机制

画像在 V3 中只用于定性“告知”，不做交叉画像后的分类打分。只有 `profile_scope = "analysis"`
的画像维度参与以下计算；`profile_scope = "label"` 只保留在来源标注中。

第一层是零额外调用的存在性信息。代码只根据 finding 已绑定的代表性 `response_ids`，按
`respondent_ref` 去重后生成 `profile_presence`。该字段只表示“代表性提及者中包含这些画像取值”，
不表示比例、不排他、不能用于组间比较。模型只能据此写“提及者包括女性玩家和高段位玩家”一类
存在性表述。

第二层是按需人群专章。章节规划最多选择 2 个明确的画像取值；代码按
`source_registry[*].profile` 筛出该人群全部开放题原文，每个人群进行一次独立定性提炼。人群专章
可以归纳“该人群反馈中出现了哪些体验”，不得据此声称相对其他人群更集中，也不得输出画像占比。

第三层是按需差异验证。章节规划模型只可输出 `suspected_skew` 待验证标记，不得直接把差异论断
写进正文。待验证 finding 最多 5 个，并最多覆盖 3 次批量验证调用；验证模型只看 finding、回答
文本和本次调用短 ID，不得看到画像。代码把验证出的完整支持玩家集合与本题玩家画像构成比较，
只有通过阈值后才生成 `skewed_toward`。传给 writer 的 `skewed_toward` 只包含画像维度、取值和
支持玩家绝对人数，不包含百分比、占比、基线人数或 lift。

偏离判断使用可配置的保守默认值：本题已知画像玩家不少于 20、画像覆盖率不少于 80%、已知画像
支持玩家不少于 6、目标画像支持玩家不少于 4、目标画像在支持者中占比不少于 50%、相对本题
基线高至少 20 个百分点且 lift 不低于 1.5。所有百分比只存在于代码内部诊断，不进入模型上下文
或报告正文。映射或验证失败时字段为空并记录原因，报告继续生成。

Writer 使用硬门禁：没有对应 `skewed_toward` 时，拒绝“更突出”“更集中”“尤其明显”等
**人群差异**表述。主语明确为产品对象的描述（如“新版界面的信息更集中”“按钮的描边更明显”）
不属于人群比较；代码仅对主语、谓语关系明确的产品描述作保守例外，不能因为句中出现产品名词
就整句放行。同句涉及画像、玩家或不明指代，以及省略主语的比较，仍按原门禁校验。Writer、
证据要点与审校修复共用此规则。任何模型生成章节中的观点级画像百分比、比例和精确人数仍
一律拒绝，偏离阈值不变。§6.19 的确定性客观题统计是独立证据类型：正文和样本解释只能用
已分配短统计引用，由代码填值；不能以此放开开放题观点的人数／比例或未验证的人群倾向。

### 6.8 阶段结果兼容指纹

若阶段二复用已完成的阶段一 findings，常规兼容性检查除 `file_sha256`、`plan_fingerprint` 和
`source_registry_fingerprint` 外，必须同时覆盖频次规则版本与 findings 提示词版本。任一规则或提示词
版本不一致时不得复用，必须重新运行阶段一，防止两套档位或提示词产物混用。

结构类重新生成可以只改变 `analysis_focus`，从而使 `plan_fingerprint` 变化但逐题模型输入完全不变。
该路径只有在代码同时满足以下条件时才可跨 plan 指纹复用：旧 artifact 与基础版本完整绑定一致；新旧
`findings_input_fingerprint` 相等；该指纹覆盖每题 `scope_key`、题名、适用人群、玩家级短 ID 映射、
实际文本及来源归属；文件、来源 registry、频次规则和 findings 提示词版本仍一致。复用后必须把 artifact
重绑到本次有效 plan 和来源契约。数据范围、筛选人群、题目输入或任一规则变化时仍须重跑阶段一。

阶段二当前只复用阶段一 findings，不复用章节规划或正文。若阶段二或阶段三以后新增“复用已完成
章节结果”，兼容指纹还必须覆盖章节提示词版本及会改变正文门禁的确定性规则版本；不得把不同
提示词或门禁产生的章节混入同一报告。

### 6.9 Writer 取舍、证据回绑与降级上限

章节规划仍须让每个 finding 恰好进入一个分析章节，以保存完整的研究素材归属；Writer 不再逐条
复述。每个普通分析章节默认最多输出 5 个正文 block（可由
`INSIGHT_V3_MAX_BLOCKS_PER_CHAPTER` 在 1—8 之间配置），核心发现最多 5 个。普通 finding 可以因
决策价值较低而不进入正文，但 `kind = "risk"`、`degraded = true` 或有 `preserve_reason` 的 finding 必须被正文 block
覆盖；多个 finding 可以合并进同一 block。

模型继续只看和输出本次调用的短证据 ID。校验先确认短 ID 属于本次证据表；若模型所选短 ID 与
该 block 的 `finding_ids` 不匹配，代码必须从这些 findings 已验证的代表性来源中确定性回绑，且
每个 block 最多保留 2 条代表反馈。全局稳定 ID 只在回绑后由代码恢复，再进入翻译与产物。诊断
记录每章回绑 block 数、完整逻辑尝试及降级原因。

Writer 输入中的每个 finding 必须附带它在本次调用内对应的代表性短 ID，不能要求模型从全文猜测
finding 与证据的对应关系。一次报告运行中的所有章节与核心发现共用同一个、已包含 session 和运行
身份的翻译命名空间，以复用同一来源的已验证译文；不得再按章节加后缀造成重复翻译，也不得跨
session 或运行复用。代表译文包含换行时，每一行都必须保持 Markdown 引用格式，不能让续行落成
报告正文或伪造新的标题、列表、表格。

频次门禁只识别“部分玩家”“大量反馈”“玩家普遍”“反复提到”“常见情形”“往往”等对提及规模
或常见程度作判断的语境，不得用简单子串误伤“部分阶段”“大量伤害”等业务词。“高度一致”、
“一致认知”、“绝对共识”、“被广泛视为”、“均提到”、“全部分析章节反复出现且未见明显分歧”
等换一种说法表达覆盖面或一致性的同义措辞，也属于频次门禁范围。写作输入会移除
finding claim 开头已有的频次主语；频次档位保留在内部 findings，不再逐 block 插入正文标签，Writer
仍不得自行改写频次。若模型正文产生禁止短语，拒绝该次写作并走既有有界重试，不做删词式中性化。
降级摘要若也含违规频次，只显示待人工复核说明与既有证据绑定，不静默产生残句。

画像精确人数门禁只匹配真正的人数结构，例如“7 名女性玩家”“女性玩家中有 7 人”或“7 名
玩家”。不得因为同一段中出现画像词，就把“4 个英雄”“2 件装备”等游戏数量误判成画像人数。

Writer 重试耗尽时，确定性降级正文同样最多 5 个 block，优先保留风险和降级 finding；当此类
finding 超过上限时须合并而不是丢弃。该取舍会降低正文对低价值普通 finding 的穷举程度，但完整
findings 产物仍保留，目的是避免降级路径膨胀成逐条清单并控制报告可读性。

### 6.10 分析主线缺失与人群专章保证

`analysis_focus` 仍只在用户提供 `qualitative_context.analysis_approach`、复用已确认主线或明确修订
主线时产生。V3 不得因为问卷存在画像列，就在 `analysis_focus` 缺失时自行推断研究主线或强行增加
人群专章。此时 `viewpoint_diagnostics.analysis_focus` 必须记录：

> 未提供分析主线，章节按问卷结构组织，未规划人群专章

该诊断表示输入中没有人群分析要求，不表示数据证明“人群之间没有差异”。

章节规划提示词与结构校验必须共同执行该限制：`analysis_focus` 缺失时，任一非空 `group_focus`
都属于无效规划，不能进入章节写作或人群 findings 提炼。若旧产物、测试桩或未来代码路径绕过规划
校验，进入 pipeline 前的契约核对还必须丢弃违规章节方案，按既有逐题 fallback 重新组织全部
findings，并在诊断中记录被拒章节与是否使用 fallback；不得仅修改诊断文案而保留人群产物。

若 `analysis_focus.expected_deliverables` 的文字能够唯一映射到一个已存在、且
`profile_scope = "analysis"` 的画像字段和取值，则该交付要求高于章节规划模型的自由取舍。模型遗漏
时，代码必须在最多 2 个人群专章的现有上限内补入对应专章；已有时去重。映射不唯一、画像值在
当前数据中不存在或超过上限时不得猜测，须在诊断中列明未满足原因。补入专章仍走代码筛选该人群
全部开放题、单独提炼的既有路径，不使用 skew 门槛；如果该人群没有可绑定发现，专章保留并如实
说明材料缺口，不得编造差异或用普通画像存在性代替人群分析。

### 6.11 suspected skew 零成本预检

差异验证模型调用和 3 次调用上限计算之前，代码必须先用本题固定画像 scope 判断候选是否可能通过
现有门槛。以下情况直接标为 unavailable 并记录确定性原因，不发送给模型：

- 已知画像玩家少于 `INSIGHT_V3_SKEW_MIN_SCOPE_KNOWN`（默认 20）；
- 固定画像覆盖率不足；
- 目标画像在本题中的可用玩家数不足以达到目标支持者下限；
- 即使把最有利的玩家集合全部视为支持者，理论最大目标占比、相对基线差值或 lift 仍无法同时通过
  当前门槛。

预检只淘汰按现有阈值数学上不可能通过的候选，不修改任何偏离阈值，也不代替后续支持者穷举和
`evaluate_skew`。通过预检的候选才按题合并调用，并占用调用上限。

### 6.12 内部证据绑定与完整证据索引

章节 Writer 和核心发现 Writer 仍只看、只输出调用内短证据 ID。新 Writer 不生成 `evidence_points`，
正文不再插入逐 block 的“证据要点”行或完整代表译文，避免证据模板挤占判断、场景及边界的篇幅。
旧产物的证据要点仅保留解析与审校兼容。代码继续验证短 ID 属于当前 block，再恢复全局 `response_id`。

代码按全报告首次出现顺序建立完整证据索引 `E-xxx`，同一 `response_id` 只保存一次完整中文译文，
并列出核心发现和各章节中的全部引用位置。行动建议固定末章之后先追加该证据附录，既有确定性
统计附录仍由后段继续追加。该设计减少正文阅读负担，但不承诺缩短报告总文件；完整译文、来源编号
和玩家主动填写的账号标识均原样保留，供内部核对追溯。

### 6.13 固定行动建议章

行动建议是所有分析章节和核心发现之后、所有附录之前的固定末章。普通建议默认最多 7 条，人群
专项建议默认最多 2 条，合计最多 9 条；不设最低条数。没有建议通过绑定门禁时仍保留本章，明确
说明证据缺口及形成方案所需补充信息，不为凑数量提出建议。

模型输出的内部 action 对象必须恰好包含 11 个字段：`id`、`title`、`action_scope`、
`target_group`、`problem`、`objective`、`design_directions`、`validation_plan`、`finding_ids`、
`evidence_gap`、`required_data`。每条建议绑定 1—3 个当前报告中的 finding ID；未知、重复或未绑定
finding 的建议一律拒绝。人群专项建议还必须指向真实人群专章，并至少绑定该专章中的 finding；
没有 `skewed_toward` 时仍不得写相对其他人群“更突出／更集中”等差异。

11 字段只存在于模型 JSON、校验和诊断产物中，报告正文不得直接罗列字段名或渲染成表格。正文采用
“建议一：标题”加叙述、再列“可考虑的设计方向：1. 2. 3.”及验证方法的写法。核心发现负责说明
“发生了什么、为什么重要”，行动建议只说明“接下来可以做什么、如何验证”，不重复证据块。绑定
finding 为 `uncertain` 或 `degraded` 时，`evidence_gap` 和 `required_data` 必须同时非空；其它建议
如果填写其中一项，也必须同时填写另一项。行动建议继续受频次、画像差异、观点级比例、精确人数、
来源数字和 Markdown 表格门禁约束。频次门禁必须覆盖“多数／大多数”“频次词 + 人群修饰 + 玩家”
等语序，同时保护“所有玩家”与“有玩家”的边界；命中后拒绝并有界重试，不删词改写。叙述装配统一收敛模型字段自带的“通过／可通过／
需要补充／需补充”前缀和句末标点，避免机械重复，但不得改写建议事实或 finding 绑定。
人群建议的来源说明统一称“该人群的定性材料”，不得把主题章内分组材料误写为来自人群专章；
目标人群同时保留真实画像字段和取值，不把客户端语言推断为母语。

`validation_plan` 若已包含“验证、核验、校验、检验、评估、衡量、复核、核对、确认、对比、比较、
监测、观察、跟踪”等验证语义，装配层只补齐句子，不再机械追加“来验证这一方向是否有效”；未包含
验证语义时才使用固定后缀。该处理只作用于确定性渲染，不修改 action 结构与 finding 绑定。

### 6.14 阶段三语义审校契约

审校范围包含模型生成的核心发现 block、普通／人群分析章节 block、样本解释、行动建议的事实依据，
以及一次全报告研究任务覆盖检查；旧产物的一句话证据要点保留兼容。确定性统计附录和行动建议的
产品可行性不在语义审校范围。建议修复仍须经过阶段二的 finding 绑定、频次、画像、数字和结构门禁。

正文实际引用的 finding 按全局 ID 去重，各自建立一个 `finding_binding` 核对单元，与正文初审同轮
装箱并发执行；不按全体回答逐项分类，不核对未被正文使用的 finding。每个单元保留 finding 到全部
代表来源的明确对应关系；来源原文在同批去重，不能只提供合并后的无归属来源池。

| 契约项 | 来源核对与正文审校 |
|---|---|
| 输入 | 已写核心发现、主题段落、行动建议实际绑定的 finding 及其全部代表原文；样本统计和研究任务保持原路径 |
| 输出 | `checked_claim_ids` 恰好覆盖本批；`issues` 绑定本单元的 `target_ids`；`finding_checks` 恰好覆盖本批 finding_binding 单元 |
| 来源关系 | 每条代表来源恰好归入 supports / opposes / context_only / mixed / unclear 之一；只输出本次短 ID |
| finding 判定 | supported / needs_review / inconclusive；正确呈现分歧的 finding 可含反例，不以“出现反例”自动判错 |
| 有效空结果 | 无对应单元时 finding_checks 可为空；无问题时 issues 可为空，但 checked_claim_ids 不得漏项 |
| 成功 | 白名单、短 ID、检查对象及字段归属、完整覆盖与去重校验全部通过；模型未返回或截断不等于通过 |
| 失败降级 | 来源核对失败关联到全部消费者并标未完成；明确问题进入消费者的一次修复与一次复审，不改原始 finding、人数或原文 |
| 预算 | 同一初审轮动态分批；每正文最多一次修复、一次复审；通常运行不设导致报告中止的阶段硬预算 |
| 诊断 | 逐 finding 关系、问题、核对终态、消费位置和最终正文状态分开保存，不能把正文已修复伪装成原始 finding 已修正 |

来源核对的 needs_review/inconclusive 会关联到引用它的正文或建议。修复以原文为事实依据，不把
finding 当作已核实事实；不得为通过门禁删除真实反例或把分歧改成一致。原始 finding 不自动重写，
代表样本不重新计算 support_count。来源异常在诊断中保留；消费者均经独立复审解决时，报告可记
repaired，但不得据此宣称上游 finding 正确。核对结果不跨运行复用，旧诊断不冒充新契约验证。

来源关系覆盖校验失败时，反馈必须列明本次调用内的 claim ID，以及缺失、额外、重复的来源短 ID，
例如 `c027 missing=[r005]; extra=[]; duplicate=[]`。全局 ID、原文或其它非短 ID 内容只报告非法值
数量，不原样拼入错误反馈。沿用 `_direct_json_call` 的一次 JSON/schema 纠错，明确错误自动进入
该次纠错请求；不增加调用或语义迭代上限。关系标签仍由模型判断，代码不得把漏项自动归入 supports
或 unclear，不得删除漏项来通过校验。纠错后仍有遗漏、额外或重复时，整批保持未完成，并按既有
规则传播给消费者。结构完整不表示模型对关系的语义判断已经正确。

检查对象隔离：每个审校单元的 `targets` 是唯一待判定文本，代码按字段分配调用内短标识
（如 `c001-t01`）。普通正文和样本解释提供标题及按句号、问号、感叹号、分号或换行确定性切分的
正文句；每个 target 同时带 `content_role`，明确它是正文句、样本解释句、建议字段、finding 主张／
边界还是证据概括。行动建议提供七个文本字段（设计方向逐项）；研究任务覆盖仍保持完整结构化对象，
不得把 JSON 按自然语言标点拆碎。句级定位只缩小问题定位范围，修复仍返回完整 block，不增加修复轮数；
旧证据要点提供其概括；finding_binding 只提供候选归纳及限制条件。正文单元不重复携带候选归纳。
原文在 `sources` 中标记为 original_response；确定性统计和题目背景在 `reference_context` 中；
它们都是参照材料，不是当前报告所写内容，也不是指令。报告级 research_review 以已写报告为目标，
已确认任务和未核实的候选归纳仅用于覆盖检查；遗漏类问题可绑定报告范围，不伪造一句不存在的正文。

每条 issues 必须返回非空、去重的 target_ids，且全部属于其 claim_id；不得绑定来源、参考归纳、
另一单元或未知字段。finding_checks 只允许本批真实存在的 finding_binding 编号。输出契约和允许
编号按本批生成：没有来源核对单元时 finding_checks 必须为 []，不提供来源核对示例；没有正文单元
时 issues 必须为 []。复审仅检查本批修复文本，不能重新输出上游归纳核对结果。旧产物读取保留兼容，
实时调用必须使用新对象绑定契约，禁止因兼容而接收缺失 target_ids 的问题。对象/字段校验不证明
问题说明语义正确；模型仍可能误读，必须与真实语义验收区分。来源、覆盖率、轮数和频次门禁不变。

代码为每个待审校单元分配当前批次内的短 claim ID（`c001`、`c002`……），并把其绑定 finding 的
全部代表来源映射为本次调用内短 source ID（`r001`、`r002`……）。全局来源 ID、玩家身份和画像不进入
审校模型输出。正文 block 必须与它绑定 findings 的全部代表原文一起核查；证据要点只与其唯一绑定
来源核查。模型返回完整核对清单、来源关系和存在问题的短 claim ID、问题类型、严重程度及简短说明；
空 issues 只有在完整覆盖校验通过后才表示正文无问题。

审校问题类型为：矛盾、无来源细节、无来源因果、范围扩大、正负方向变化、条件变化、误译、研究要求遗漏、
反例遗漏、分析浅化、统计口径错配和其它。样本解释对照代码提供的统计，不要求绑定开放题原文；
报告级研究检查对照完整分析主线、任务分配、findings 与已写正文，不增加全量逐回答分类。
研究任务遗漏只标注待人工复核，不靠修复调用重新规划整份报告或创造新的证据绑定。
证据要点发现问题时由代码清空概括，正文确定性回退为“详见 E-xxx”，完整译文仍在证据附录。正文
block 发现问题时，最多进行一次合并定向修复；普通 block 修复只能改 `heading` 与 `body`，不得改 finding、来源、
画像或统计绑定。修复文本必须重新经过 Writer 的频次、画像、数字和 Markdown 门禁，再接受一次独立
复审。修复无进展、格式无效、调用失败或复审仍有问题时立即停止，不做迭代收敛。
行动建议修复只允许改变 title、problem、objective、design_directions、validation_plan、evidence_gap、
required_data 七个文本字段，不得改 id、action_scope、target_group、finding_ids。依据不确定时必须
说明缺口和补充数据，不将建议的待验证设计方向当成已发生事实。
样本解释在初审或复审后仍为 `needs_review`／`incomplete` 时，不得继续进入正文；代码将解释置空，
装配层退回确定性样本口径说明与已选表格，未解决原因继续保留供人工核对。

初审按全部计划单元的实际序列化体积动态拆分，不设总批数上限。常规批次以 90,000 字符为装箱目标，
同时最多包含 24 个审校单元（含 finding_binding），控制输出体积但不保证模型不会截断；输出上限仍为
12,000 tokens，截断按未完成处理。若单个单元连同其全部绑定
来源自身超过装箱目标，不得删减来源或跳过该单元；代码必须将它隔离成单独批次照常调用，并在诊断中
标记超目标输入。只有该调用实际失败时才记为 `incomplete`。初审、正文定向修复和修复
复审三个阶段均使用有界并发，默认并发度为 4，可在 1—8 之间配置。逻辑调用数由三个阶段的实际批次
数决定，不再设置固定的 4 次硬上限。

所有初审发现的正文问题都必须进入动态修复批次；所有通过代码门禁的修复结果都必须进入动态复审批次。
这不改变收敛边界：每个正文 block 仍最多修复一次、复审一次，不因复审失败继续迭代。超目标独占调用、
普通批次或复审调用最终失败，以及无法获得终态时，均不得静默遗漏，必须显式进入 `incomplete` 或
`needs_review`。审校默认使用 `gpt-5.6-terra`，fallback 为 `gpt-5.6-sol`，reasoning 为 `high`，
输出上限 12,000 tokens；配置来自 `.env` 与 `app/core/config.py`。审校超过 300 秒只告警，不中止报告。
单次 `_direct_json_call` 自带的协议切换、模型 fallback 或一次 JSON/schema 修复只增加上游尝试数，
不产生新的语义迭代轮次。

报告级审校状态固定为：

- `passed`：全部计划单元完成核查且没有问题；
- `repaired`：发现的问题已通过证据要点回退或正文定向修复解决；
- `needs_review`：流程完成，但正文单次修复后仍有问题或修复未通过代码门禁；
- `incomplete`：存在无绑定来源、超目标独占调用最终失败、其它初审失败、复审失败或内部终态缺失；
- `skipped`：没有模型生成的可审校正文。

每个计划单元还必须恰好落入一个终态：`passed / evidence_fallback / repaired / needs_review /
incomplete`。各终态数量之和必须等于计划单元数。初审覆盖率按“取得有效初审结果的单元数／全部计划
单元数”计算；正文修复复审另记覆盖率，不能把进入修复但未完成复审的单元算作修复通过。

`needs_review` 与 `incomplete` 都不得丢弃报告。代码必须在 H1 标题后逐项列出章节、标题和问题说明，
明确它们“需要人工复核、不代表一定错误”；前端在收到最终完成事件后提示报告已保存及待复核数量。
诊断至少保存计划／已审单元数、两类覆盖率、逐单元终态分布、各阶段批次数、配置与实际峰值并发、
每次逻辑调用、超目标调用数、按步骤归属的上游失败类别、上游尝试数、输入字符、输出上限、模型、耗时、停止原因、
已解决与未解决项。审校模型或模型 fallback 不能成为整份报告保存的单点故障。

风险分级可以用于未来调整调度顺序，但不得以抽样或跳过低风险单元代替 100% 初审覆盖。正文 block
继续核对其 findings 的全部代表来源；不得为了减少输入改成只看正文展示的 1—2 条证据。来源核对与
正文初审同轮执行，不另建全量预分类或增加迭代轮次。本轮 Q7 隔离闭环仅复用已保存的提炼结果，
最多 18 次逻辑调用、72 次上游尝试；这是显式实验上限，不影响正常报告告警不中止的原则。

### 6.15 频次门禁持续发现

完整报告生成后，代码扫描模型生成的核心发现、分析章节、证据要点和行动建议，寻找“数量／比例／
普遍性词 + 玩家／受访者等主体”的宽泛模式，包括前后语序和画像修饰。扫描不覆盖代码生成的样本
概况、提及情况标签、统计附录或完整译文，避免把确定性数字和玩家原话当作 Writer 绕过。

命中项只写入 `viewpoint_diagnostics.frequency_review` 的待人工确认清单，记录位置、字段、命中文本和
上下文；不得自动改写正文、阻断保存或直接扩充生产黑名单。只有人工确认确属绕过后，才在后续单独
批准的改动中更新黑名单与回归样例。该机制用于让门禁随真实使用收敛，不把高召回扫描误当成质量
判决。

### 6.16 本轮未包含事项

阶段三不实现追问时精确人数计算协议，也不宣告人群专章或人群专项建议语义验收通过。后者必须等待
包含明确 `analysis_focus.expected_deliverables` 的真实运行完成；自动测试只能证明强制规划和降级
路径可执行，不能代替真实模型语义质量验收。

### 6.17 重新生成指令的影响分类与能力边界

V3 的非空重新生成指令必须在章节规划前完成影响范围分类，分类维度固定为：仅措辞、章节结构、分析
主线／`expected_deliverables`、数据范围；混合要求保留全部命中维度。首次生成或空指令不增加该步骤。

- 仅措辞：沿用基础版本 plan，将原始要求传给章节、核心发现和行动建议 Writer；findings 按完整兼容
  指纹复用。
- 章节结构或分析主线：在章节规划前额外形成完整六字段、仅供本次运行使用的 revised
  `analysis_focus`；基础 plan 的题目、样本、筛选和统计口径不变。章节规划及全部下游必须重跑，findings
  只有满足 6.8 的逐题输入等价证明时才可复用。
- 数据范围：报告重生成阶段不得执行，必须在正文模型调用前显式拒绝，并引导用户回到数据与方案确认
  步骤；不得生成空版本。
- 跨章节双人群贯穿：当指令中的两个取值能够唯一映射到同一个 `profile_scope=analysis` 画像时，代码
  先对每个人群的全部开放题原文各提炼一次，再把全体 findings 与两组人群 findings 一起按主题分配
  到真实分析章节；不得按“人群 × 章节”重复提炼。章节 Writer 仍是一章一次调用，并须在章内用明确
  标签分别呈现两组视角；不得据此自行声称比例差异、人群倾向或优劣比较。无法唯一映射、涉及三个或
  更多人群时仍属能力外要求，必须显式拒绝，不得静默降为单个人群。
- 画像映射必须同时保留实际字段含义与取值。“客户端语言”“界面语言”“回答语言”不得推断为
  “玩家母语”；没有母语画像字段却要求按母语分组时，必须说明缺少资料并拒绝新增版本。即使两个
  选项匹配，也不得覆盖分类失败或数据范围拒绝；主线修订和正文校验同样不得擅自改换画像维度。
- 跨章节双人群容量：完成真实章节分配后，按 Writer 的实际序列化输入逐章执行 90,000 字符硬预检；
  来源须先按 `response_id` 去重，不能按 findings 数量线性外推。通过预检的章节获得双人群 findings；
  未通过的章节只移除本章的人群 findings，退回普通写法，其他章节继续使用人群视角，整份报告不得
  因单章超限失败。每个退回章节必须在 `viewpoint_diagnostics` 记录原因、实测字符数和普通写法字符
  数。不得通过压缩、截断或抽样绕过预检；若某一人群提炼失败，同样按章级普通写法安全降级并记录。
- 跨章节双人群材料／分配不足：某章未分配齐两组 findings 时，只让该章退回普通写法，不得将这条
  章级条件用作整份章节方案失败的依据；其他材料齐全且容量合格的章节继续分组。全体 finding 覆盖、
  每个 finding 恰好分配一次、ID 与统计引用等全局门禁保持不变。普通降级输入字符数必须包含实际
  Writer 的降级约束文本。诊断分别记录人群提炼状态、章节规划状态、预检启用章数及最终写出分组章数，
  不得把提炼成功等同于报告已经呈现人群视角；写作重试耗尽后的退回也必须反映在最终诊断中。
- 分类或主线修订的模型输出无法通过契约时，按能力不明处理并拒绝本次生成；不得带着旧 plan 继续。
- 画像维度门禁逐字段、逐列表项和逐分句检查。“不涉及母语分析”“本报告不分析母语差异”等明确
  否定不是分析要求；`avoid_structures` 只表达禁止内容，不作为正向要求扫描。否定不得跨字段、跨
  分句或跨不同的母语提及生效；真实母语要求、混合肯定要求与双重否定仍须有实际母语字段。
- 拒绝也必须保留证据：后端通过 `report_regeneration_diagnostics` 透传分类原始结果、最终判定、
  门禁版本、失败阶段、调用错误、输出长度与分段耗时；画像门禁拒绝时保留未采用的候选主线和具体
  字段，显式标记 `candidate_applied=false`，不得写成有效方案或新增版本。回放失败产物保留这些
  诊断、上游尝试、可用 token、用量完整性及前后方案／版本摘要与哈希；未知 token 为 null，不冒充
  零消耗。尝试事件按字段白名单记录，不保存密钥、请求头、HTTP 正文或完整玩家原文。
  分类调用失败与明确能力外拒绝须分开表述；不得只因接近超时阈值就断言超时。既有模型、提示词、
  超时、重试上限、缺字段拒绝和容量规则不变，不增加模型调用。

分类结果、提示词版本、原始指令、revised `analysis_focus` 与调用诊断必须进入新版本
`input_snapshot.v3_regeneration` 和 `viewpoint_diagnostics.regeneration`，使历史版本可解释、可复现。
通过确定性预检的非空指令增加 1 次分类逻辑调用；缺少实际画像等确定性拒绝不调用模型。
章节结构／分析主线类再增加 1 次主线修订逻辑调用。JSON
修复或模型 fallback 只增加上游尝试，不改变逻辑调用口径。关闭 `INSIGHT_REPORT_V3_ENABLED` 时，新
insight 报告走旧引擎；已保存且绑定 `insight_v3` 的版本仍可查看与导出，但重新生成必须明确拒绝，
不得静默退回旧引擎。

### 6.18 真实 UI 回归清单

每次 V3 交付前由业务验收人在浏览器完整执行一次；交付报告逐项填写 `PASS / FAIL / NOT RUN`、版本号
或截图等证据，以及自动测试无法覆盖的原因。判据如下：

1. **上传 XLSX → 列识别与确认**：页面显示的文件名、样本数与实际文件一致；每列题型、画像用途和
   选项可见且与人工确认一致；确认后返回页面或进入下一步，已确认值不被默认值覆盖。
2. **填写分析思路（含人群要求）→ 方案确认**：方案卡中必须可见核心问题、明确人群、组织方式和
   `expected_deliverables` 对应内容；不能只有输入框保存成功而方案正文没有体现。
3. **观察逐题进度**：计数从 `0/N` 单调递增到 `N/N`；每项显示真实题名、玩家人数及“名玩家”单位；
   每题最终落入 complete／degraded／skipped 之一，顶部汇总与详情数量一致。
4. **生成完成**：只新增一个版本；显示的是本次运行耗时而非从方案确认累计的时长；版本号连续；标题
   下未解决项数量与展开后的逐项清单一致，刷新后仍一致。
5. **提交结构调整要求 → 重新生成**：受支持要求保存其基础版本与原始指令并新增一个版本；超出能力的
   要求在正文生成前显示具体原因，且不新增空版本或“看似成功”的未改版本。
6. **对比两版章节结构**：新版本 H2 标题、顺序和正文组织能逐条映射到本次要求；旧版本仍可切换查看；
   两版样本、题目与确定性统计在未要求改数据时保持一致。
7. **导出 Word 与飞书**：两种导出均可打开；正文位于完整证据索引之前，确定性统计附录位置正确；
   每个正文 `E-xxx` 可在证据附录找到且完整译文不截断、不重复，正文与附录分隔清楚。

自动测试不能替代这份清单：mock/CLI 无法观察 SSE 在真实 DOM 中随时间更新的状态，也不能证明模型
生成的自然语言章节确实落实结构要求；版本切换、浏览器缓存和阅读位置属于浏览器状态；Word 版式与
飞书文档属于真实导出及外部集成的视觉结果。凡清单发现而自动测试未发现的问题，交付报告必须指出
对应盲区，不能只记录修复结论。

### 6.19 研究质量改造（2026-10-10 批准）

本节取代 6.4、6.7、6.9、6.12、6.14 中与下列规则冲突的旧行为；不改变前四步、频次档位、
skew 阈值、双人群上限、90,000 字符章级人群容量预检及最多一次语义修复／复审的边界。

| 阶段 | 输入与输出 | 取舍与成功条件 | 失败与诊断 |
|---|---|---|---|
| 确定性材料适配 | 冻结方案、已有 stats_md/表格、同一版本数据；输出带口径的统计目录及代码管理的同玩家关系 | 保留既有总体表与交叉表；同口径去重，不按题名丢表；不改变原统计 | 无法解析或关联不唯一时记录缺口，不猜测、不改前四步 |
| 逐题提炼 | 全题原文；输出 findings 及保留理由 | 允许合并普通同义观点；重要具体问题、条件与反例应独立保留并绑定短 ID；不得以代表样本估算精确比例 | 提示词和 schema 更新，旧产物不得按新契约复用；代码无法保证发现所有漏提，真实抽查单列 |
| 章节与核心写作 | 完整主线、分配 findings、对应来源、选中统计与同玩家关联 | 按判断、理由／情境、反例／条件、业务意义组织；核心仍最多 5 条；重要保留项必须被覆盖 | 有界重试后局部降级；未兑现的研究任务在正文与诊断同时说明 |
| 样本解读 | 核心写作调用同时返回独立样本解读；只使用代码选定的统计 | 不设最短字数，最多 500 字；解释结构及解读边界，不介绍程序实现 | 与核心发现分别校验，解读失败只回退为确定性样本信息与表格 |
| 语义与任务审查 | 已绑定原文、确定性统计、章节任务及正文 | 核对事实、范围、分母、关键反例和任务覆盖；不检查产品方案实施可行性 | 动态装箱、有界并发；最多一次文本修复、一次复审；遗漏或不完整审查标注，不无限再生成 |

客观题确定性统计是独立证据类型，含题目、统计范围、表头与分母信息。允许在选定统计绑定下
描述客观选择分布及交叉表，不把这种描述称为因果或显著性证明。没有对应统计绑定的画像人数／
比例仍禁止；开放题观点人数、比例和群体倾向仍走原契约，不以代表性 response_ids 推导。
统计数值优先以单元格短引用回填（如 `[S:s001-r001-c002]`），保留该单元格的题目、行选项、
列名、整行和口径供审校；代码不另算合计或比例。行级短引用保持兼容，但不是脚注，不能将
整行内容在每个句尾展开为大段重复统计。模型仍不得用无绑定数字替代短引用。

同玩家关联只发生在代码可核对的同版本材料内；模型只看调用内玩家短编号和来源短编号，不看
respondent hash、全局来源 ID 或结构化明文身份。关联只说明同一人作答，不能支撑群体倾向。
不把当前章未分配的全部回答自动加入，不通过截断、压缩或抽样绕过既有容量门禁。

研究任务须区分客观统计比较、分支题原因分析和人群定性专章。已有统计中的全部选项保留；
某选项未被问及原因时明确材料缺口，不编造原因、不视为没有意见。不因主线缺失自行增加人群
专章，不扩大双人群定性贯穿的能力范围。无法满足的交付项不能只藏在内部诊断中。

正文不再逐 block 显示频次标签或“证据要点”；新 Writer 不生成 evidence_points。内部 finding、
来源绑定和完整证据附录保留，附录列出对应章节及段落。旧版本内容不回写，原文入口文案改为
“查看全部回答”，查询行为不变。禁止用机械删除频次词改写整句；违规表述走有界重试／修复，
不能静默产生残句。旧证据要点仅用于兼容已有产物，不作为新正文必要字段。

2026-10-10 增量确认：有有效来源绑定的“有玩家／有受访者提到”只表示存在性，允许进入正文；
不能据此声明比例、常见程度、排他性或群体差异。没有来源绑定时仍拒绝。“部分／多数／普遍／
所有玩家”等规模与一致性断言继续拒绝，不能因句中含“有玩家”而豁免其它门禁；语义审校核对
存在性后面的内容是否确由绑定材料支持。此项覆盖旧正文门禁对所有“有玩家”一概拒绝的行为，
不改阶段一频次档位或 support_count。

2026-10-12 增量确认：明确表达“无法判断是否普遍”“不清楚普遍程度”等证据边界，不属于观点频次
断言。代码只在同一分句内同时存在不确定／否定语义及“是否”或“程度、范围、规模、比例、频次、
数量”等边界词时放行；后续分句中的“玩家普遍认为”等正向断言仍拒绝。该例外不允许借否定句掩护
另一条频次结论。

| 写作恢复阶段 | 输入与成功条件 | 上限与失败处理 |
|---|---|---|
| 根结构校验 | 章节身份、JSON 根字段、非空 blocks、数量及唯一 block ID 合格后才拆块 | 无法确认则整体拒绝，复用原 JSON 纠错边界 |
| 逐块校验 | 每块独立校验字段、来源、数字、频次和人群；合格块冻结 | 不因另一块失败重写冻结内容；语义正确性仍须后续审校 |
| 定向修复 | 仅返回失败块的指定 ID；携带其相关 findings、去重来源、已绑定统计及缺口 | 占用原章级最多 1+2 次逻辑调用，不另叠加循环；每次仍最多一次 JSON 纠错；修复无新增合格块则停止 |
| 最终组装 | 再核对唯一 ID、来源、必写材料、人群分组；只替换失败块 | 部分未完成时整章 degraded，保留合格块并显示缺口；无空位补缺时只在末段之后追加代码生成的缺口提示，不改冻结的模型段落 |

阶段三仍最多一次语义修复、一次复审；不是为 Writer 再增加无限修复机会。诊断记录每轮模式、
输入字符、逐块错误、冻结与未完成 ID、缺失必写材料、人群缺口及停止原因。缺口块的 ID 绑定
不能算作已形成实质分析。统计修订可使用代码从已绑定同一行展开的原单元格引用，不能扩展
到其它统计行／表，不能重新计算数字。行总计与标星的小单元格保持不同口径。

2026-10-10 源头语义与局部降级兼容增量：

- 事实性反例必须独立成 finding，以 `preserve_reason=counterexample` 保留，并绑定其自身
  `response_ids`；不能将相反观点的来源或人数混入主观点。`caveat` 只说明当前发现的证据边界、
  未知条件或待核实之处，不承载另一事实。`claim/caveat` 中作为独立标记出现的本次调用短 ID
  由代码拒绝，只允许通过结构化 `response_ids` 绑定；不自动删改输出，不改原回答或脱敏账号。
  该门禁不是语义验证器，不能判定所有无编号事实是否有依据。提示词须保留“能／不能、允许／
  不允许”等模态与完整谓语，不压缩成无方向的名词。提炼版本更新为 v6-bound-counterexamples。
- 提炼及章节／核心写作必须保留原回答的肯否、时态、主体、触发条件与推测程度，不能因
  原文看似违背常识而补否定词、补因果或改成另一种机制。矛盾或含混材料保留为待核实线索；
  finding 与其绑定原文冲突时以原文为准，不能用摘要覆盖原文。同玩家关联只证明共现，
  不能证明其客观选择是另一回答的原因。提示词版本更新使旧提炼不能按新版本复用。
- 人群呈现以实际保留的合格 block 所绑定的 group findings 为准，不以材料分配、提炼成功或
  整章 complete/degraded 代替。缺口块、整体写作回退及无来源／未知／混组绑定不授予人群资格。
  最终逐章状态为 enabled（两组均有合格段落）、partial（仅有一组合格段落）、
  ordinary_fallback（无人群合格段落）；保留 retained_groups、missing_groups、failed_block_ids。
  诊断分别计 written_group_chapter_count、written_partial_group_chapter_count、
  written_fallback_chapter_count，三者之和等于总章数。普通段落失败不抹去两组已合格内容。
  原容量／材料预检普通回退语义不变；partial 进入 unresolved，不伪称整章已退回普通写法。
- 人群专项建议仅可使用实际保留的人群段落中绑定的对应 group finding。失败、未写出或只被
  分配的 group finding 不进入建议输入、不得借另一组合格段落获得资格；普通 finding 可作
  背景，但不能替代对应人群依据。诊断与建议资格共用同一确定性投影，不增加模型调用。
- 已确认的规模措辞“相当数量的描述”“少量反馈”纳入正文频次门禁，仍走原有界修复，
  不删词、不开额外循环；不据此宣称黑名单完备。

正常提炼仍每题一次，正常写作仍每章一次，样本解读与核心共用一次；新增研究任务审查的实际
调用数按序列化输入动态装箱记录，不恢复逐条 classify。审查只覆盖选用证据与已提炼材料，
不宣称能找全原始数据的所有遗漏。记录输入字符、调用／上游尝试、token 完整性、阶段耗时、
任务兑现与未兑现项、重要 finding 覆盖、样本解读状态、正文／附录字符。时间只告警不中止。

真实验收先用卡牌乱斗隔离副本，不把参考报告放进生成输入；逐条核查跨题情境、重要异常、
全部偏好选项和证据边界。通过内容核对后再回放三份既有数据。自动测试与审校覆盖率不等于
研究质量 GO；保留浏览器验收及人工语义验收的独立结论。

## 7. 阶段一验收

1. 模型输出字段白名单不含任何原文字段；带 `quote` 的输出必须拒绝。
2. 同一玩家多条文本只获得一个模型短 ID。
3. 模型上下文不包含全局来源 ID 或玩家哈希。
4. 短 ID 经校验后才能翻译为全局来源 ID。
5. 单题失败时其他题继续，全部原文 ID 进入降级结构。
6. 非开放题不进入 questions；无有效回答的开放题才是 skipped。
7. 自动和人工前四步 session 进入阶段一后产生相同结构。
8. 三份批准的 XLSX 各完整运行一次；金币路固定题目子集先比较并发 2、4、6。
9. 随机抽取 5 个 finding，人工按唯一玩家核对 `support_count` 与原文实际条数的偏差，并写入交付报告。
10. 记录成功、失败和降级实际发生次数，不只报告成功路径。

只有 mock/静态测试通过时，阶段一真实语义质量仍为 NO-GO。真实模型回放和人工抽查完成后，
才能给出阶段一验收结论。
