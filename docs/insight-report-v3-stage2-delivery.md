### 1.2 阶段二写作流水线

- 可复用兼容的阶段一 findings；复用指纹同时校验文件、方案、来源注册表、频次规则版本和 findings
  提示词版本，不兼容时重新提炼。

- Writer 只接触本次调用内短证据 ID。代码校验 ID、按 finding 回绑代表来源、恢复全局 ID，并在同一
  session/运行命名空间中复用已验证译文；每个 block 最多两条代表反馈。
- 代表反馈的每一行均以 Markdown 引用格式输出，避免多行原话的后续行被误当成报告正文。
- V3 组装前三个固定章节、核心发现、动态分析章节、固定行动建议末章、完整证据索引和统计附录；
  不再调用依赖 `## Part X` 标题定位的 `inject_qualitative_stats`，因此不会静默丢失逐题客观统计。

### 1.3 三层画像机制

1. **存在性，零额外画像调用**：`profile_presence` 只由代表性 response IDs 计算，语义限定为
   “提及者中包含这些画像”，不表示比例、不排他、不可用于比较。
2. **人群专章，按规划触发**：规划器要求某人群专章时，代码按 `profile_scope = analysis` 的画像值
   筛出该人群全部开放题原文，单独提炼；本轮三个真实方案均未规划人群专章，因此真实运行调用数为 0，
   路径由单元和集成测试覆盖。
3. **差异论断，按需验证**：模型只能提出有限个 `suspected_skew`。代码再对候选做支持玩家验证并在
   内部计算偏离；只有得到 `skewed_toward` 的 finding 才允许 Writer 写“更突出／更集中／尤其明显”。

模型上下文不包含画像比例。观点级画像百分比、比例和精确人数一律拒绝；样本概况中来自确定性 stats
的样本结构数字不受此限制。画像映射或差异验证失败时字段为空、记录原因并继续报告，不放行差异表述。

### 1.4 确定性写作门禁

- 频次表述由 finding 契约和代码插入。模型正文中的“部分玩家”“普遍”“反复提到”“常见情形”
  “往往”等措辞会被中性化；“部分阶段”“大量伤害”等游戏语义不误伤。
- 真实报告人工抽查发现“高度一致”“一致认知”“绝对共识”“被广泛视为”“均提到”“全部分析
  章节反复出现且未见明显分歧”等同义绕过。当前代码已把这些同义表达纳入同一门禁，并完整记录每个
  block 的改写词。
- 画像精确人数门禁只拦截“7 名女性玩家”“女性玩家中有 7 人”等人群计数，不误伤“4 个英雄”
  “2 件装备”或 `Realme C17` 等业务内容。
- 数字、画像差异、证据 ID、必保风险和降级 finding 均在代码侧校验；模型重试耗尽时，确定性降级
  路径仍遵守相同 block 上限、证据绑定和频次中性化规则。

### 1.5 技术 GO 后第三步补充

- 增加固定“行动建议”末章。模型内部使用 11 字段 action 契约；每条建议绑定 1—3 个当前报告
  finding，普通建议最多 7 条、人群专项最多 2 条。正文只渲染叙述、设计方向和验证方法，不暴露
  内部字段；没有合格建议时保留章节并如实说明证据缺口。
- `analysis_focus.expected_deliverables` 能唯一映射到 `profile_scope = analysis` 的画像取值时，代码保证
  规划对应人群专章；完全缺失主线时不凭画像列猜测，并写入“未提供分析主线，章节按问卷结构组织，
  未规划人群专章”。
- suspected skew 在模型调用前增加数学可达性预检；已知 scope 小于 20、画像覆盖不足、目标人群规模
  不足或理论上不可能同时通过现有阈值的候选直接淘汰，不占调用上限，也不修改阈值。
- 正文以一句话“证据要点”引用 `E-xxx`；完整译文移入附录，同一 response 只保存一次并列出全部
  引用位置。概括失败只显示“详见 E-xxx”，不退回截断原文。
- 真实回放中补齐“多数／大多数”“不少老玩家”等频次词形、`所有玩家` 边界，以及行动叙述的重复
  前缀和标点。修正只发生在确定性校验与装配层，不改变 finding、support_count 或完整原文。

  `所有玩家` 与 `有玩家` 的边界。由于这是纯确定性后处理，未重新调用模型；最终隔离 markdown 已
  按同一批模型结果和最终规则校正。
- **符合业务预期，不是隐私风险**：打野报告一条代表反馈包含玩家主动写入的游戏账号标识。该标识
  用于内部问题核对与追溯，数据收集时玩家侧已知晓，报告也只在内部业务范围使用。旧引擎原本就在

  只有自动测试证据，尚无真实模型语义验收。

### 生成速度与成本

- **特定条件下必然发生**：章节越多、原文越长、Writer 或验证重试越多，调用数、token 与耗时越高。
- **必然发生**：有可用 findings 时，固定行动建议章新增 1 次逻辑模型调用；本轮三份均一次成功。
  证据要点与行动结构也会增加写作输入/输出 token，但没有额外逐条证据调用。
- 三次新鲜全流程分别为 612.041 / 602.249 / 964.883 秒和 1,067,874 / 1,124,789 / 1,441,152
  tokens。金币路旧基线复用了 findings，不能直接比较；打野较旧新鲜回放更快、战备更慢且出现单章
  长尾，说明上游波动足以覆盖新增调用的部分影响，不能据此给出固定耗时增量。
- skew 预检在本轮把 15 个候选中的 12 个在调用前淘汰，只对战备余下 3 个调用验证。代价是当前保守
  阈值下不可达的候选不会获得探索性模型判断；收益是它们不再消耗验证调用。
- 默认 20 分钟仍只告警不中止；硬超时只在显式试验参数下生效，不会因时间目标作废已完成题目。
