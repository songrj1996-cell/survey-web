# 多模态第 0 批：外部平台技术验证报告

## 一、报告范围与结论口径

本报告记录第 0 批截至 2026-08-12 的验证结果，并为第 1 批统一数据契约提供边界依据。结论按以下证据等级区分：

- **公开页实测**：使用脱敏、非生产 Google Forms 样例完成的浏览器和请求行为验证；
- **匿名 REST 实测**：未携带 OAuth Bearer token 调用官方 REST API 得到的真实响应；
- **授权 REST 实测**：使用非生产账号和 Google OAuth Playground，仅授予 Forms 问卷结构及回复两个只读 scope 得到的真实响应；
- **官方契约确认**：由 Google 官方 REST Discovery、开发者文档和帮助文档确认；
- **本地契约覆盖**：已进入脱敏 fixture、Schema、校验和单元测试，不等于外部平台连接器已上线；
- **No-Go / 延期**：证据不足时明确停止生产实现或移交后续批次，不用页面抓取或推测补齐证据。

本报告的核心结论是：

1. Google Forms 公开答题页的开放、停止收集和恢复流程已完成实测，停止收集不会删除既有回复；
2. Google Forms 真实 OAuth 前后对照、停止/恢复状态 API、历史回复和图片临时地址下载已完成；外部 API 可行性 Gate 通过，但生产连接器仍未实现；
3. Google 问卷没有可作为通用原生备份的官方结构化导入/导出文件格式，项目采用“API JSON + 立即下载的图片快照”为高可信输入；
4. 倍市得原问卷 Excel 继续 Go，在线连接器因缺少可审计的正式接口契约、授权实测、稳定 ID 和合规证据而 No-Go；
5. Google Drive 生产连接器 No-Go，Shared Drive、文件上传题和完整权限矩阵延期到第 3 批；
6. **第 0 批允许以“已验证事实 + 明确 No-Go / 延期项”收口，不要求所有连接器都 Go。**

本报告不代表 Google Forms、倍市得或 Google Drive 的生产连接器已经实现。

## 二、Google Forms 公开页开放、停止与恢复实测

### 2.1 实测步骤与结果

测试仅使用脱敏非生产问卷。报告不记录表单 ID、回答原文、Cookie、临时素材地址或账号信息。

| 顺序 | 操作 | 实际结果 | 结论 |
|---|---|---|---|
| 1 | 在开放状态访问答题页 | `viewform` 正常展示问卷结构 | 开放状态的公开页可用于人工对照，但不是稳定连接器来源 |
| 2 | 记录停止前回复数量 | 测试问卷共有 4 条回复 | 作为停止/恢复前后对照基线 |
| 3 | 在管理端停止接收回复 | 原答题入口重定向到 `closedform`，不再展示可填写结构 | 停止收集会使发布页不可用于结构抓取 |
| 4 | 对停止前已知的提交入口直接 POST | 未新增回复，回复总数仍为 4 | 不能通过复用旧提交入口绕过停止收集 |
| 5 | 在停止状态检查既有回复 | 4 条既有回复仍保留 | 停止收集不会清空历史回复 |
| 6 | 恢复接收回复并重新访问 | `viewform` 和原问卷结构恢复 | 人工临时恢复后可重新核对公开页结构 |

### 2.2 对产品流程的约束

- `closedform` 只能证明当前公开答题页不可填写，不能替代官方 API 的发布状态字段。
- 停止收集后不得继续抓取发布页并声称拿到了完整问卷；页面已经没有可依赖的题目结构。
- 直接 POST 没有新增回复，说明“停止收集”不能被旧表单字段安全绕过，也不应尝试绕过。
- “由问卷所有者临时恢复收集后重试”在本次脱敏样例中不会删除已有回复，但会改变真实业务收集状态并重新开放答题入口。因此只能作为**人工、显式确认、有时间窗口和审计记录**的保底步骤，连接器不得自动切换该状态。
- 生产快照完成后不得持续依赖发布页可访问性。

## 三、Google Forms REST 与 OAuth 验证

### 3.1 匿名调用基线

在 Microsoft Edge 已登录 Google 账号的前提下，不携带 OAuth Bearer token 直接调用 Forms REST API：

| 接口 | 匿名实测 | 说明 |
|---|---|---|
| `forms.get` | HTTP 401 | 浏览器登录 Cookie 不等于 Forms API OAuth 授权 |
| `forms.responses.list` | HTTP 401 | 能在网页中查看回复，不代表 REST 请求拥有回答读取 scope |

结论：Edge 登录态只属于浏览器会话，不能当作本系统的 OAuth token，也不能通过复制 Cookie、编辑页请求或浏览器缓存替代 OAuth。生产连接器只能使用用户明确授权、按用户隔离的 OAuth 凭证。

### 3.2 OAuth 前后对照结果

| 检查项 | 授权前 | 授权后实测 | 判定 |
|---|---|---|---|
| `forms.get` 读取脱敏问卷定义 | HTTP 401 | HTTP 200；31 个 Item、23 个稳定 `questionId`、4 个图片输出 | 只读结构 scope 有效 |
| `forms.responses.list` 读取脱敏回复 | HTTP 401 | HTTP 200；4 条回复、74 个答案条目、23 个唯一答案键 | 全部答案键均能映射到问卷 `questionId` |
| 停止收集后 API 读取定义 | 无授权时不可读 | `forms.get` 仍为 HTTP 200；`isPublished=true`，`isAcceptingResponses=false` 以默认值省略表达 | 停止收集不等于取消发布，API 结构仍可读 |
| 停止收集后 API 列出既有回复 | 无授权时不可读 | `responses.list` 仍为 HTTP 200，4 条历史回复完整保留 | 读回复不依赖公开页是否开放 |
| 图片 `contentUri` 下载 | 无授权时无法取得地址 | 取得地址后，4/4 未携带 Bearer 的下载请求均为 HTTP 200，均为 `image/png`；单图约 369 KiB～934 KiB | 已验证“授权取结构、立即下载、哈希化”链路；URL 本身按短期敏感凭据保护 |
| 图片地址稳定性 | 官方契约指明限时有效 | 紧接着再次 `forms.get` 时 4/4 `contentUri` 全部轮换，对应下载内容哈希完全一致；`sourceUri` 全部缺失 | 绝不能持久化 URL，只能持久化下载字节与内容哈希 |
| 恢复收集 | — | API 回到 `isAcceptingResponses=true`，公开页回到 `viewform`，回复数仍为 4 | 停止/恢复对照闭环 |

本次使用 `access_type=online` 的短期访问令牌，未生成 refresh token。实测完成后调用 Google 撤销端点返回 HTTP 200；使用原令牌再请求 `forms.get` 返回 HTTP 401 `UNAUTHENTICATED`，Google 账号的第三方授权列表也已不再显示 OAuth Playground，确认授权已失效并移除。报告只记录 HTTP 状态、字段形状和脱敏计数，不记录 token、授权码、表单 ID、回答原文或临时 `contentUri` 的值。

### 3.3 专用 scope 边界

读取问卷定义的专用最小 scope：

```text
https://www.googleapis.com/auth/forms.body.readonly
```

读取回复需单独申请：

```text
https://www.googleapis.com/auth/forms.responses.readonly
```

两者只授权 Google Forms 对应资源，不授予任意 Google Drive 文件的读取或下载权限。回答内若出现 Drive 文件 ID，仍需独立的 Drive 授权与文件级访问权。

官方参考：

- [读取 Google Forms 内容和回复](https://developers.google.com/workspace/forms/api/guides/retrieve-forms-responses)
- [Google OAuth 2.0 Web Server 流程](https://developers.google.com/identity/protocols/oauth2/web-server)

## 四、Google Forms 官方真实结构结论

### 4.1 发布状态的真实嵌套结构

`publishSettings` 不是直接放布尔值。开放时真实返回为：

```json
{
  "publishSettings": {
    "publishState": {
      "isPublished": true,
      "isAcceptingResponses": true
    }
  }
}
```

停止接收后，实测 JSON 依照 protobuf JSON 默认值规则省略 `false`：

```json
{
  "publishSettings": {
    "publishState": {
      "isPublished": true
    }
  }
}
```

因此，`publishState` 已存在时，缺失的 `isAcceptingResponses` 应按布尔默认值解码为 `false`；整个 `publishSettings` 缺失的旧表单则仍必须标记为未知，不能推断为开放或关闭。`revisionId` 也不能代替发布状态：它是不透明、短期有效的内容版本标识，而且官方明确说明表单内容版本不包含 `publishSettings`。

### 4.2 Item、Question 与 Grid

- 每个 `Item` 有 `itemId`；`pageBreakItem`、`textItem`、`imageItem`、`videoItem` 等非题目 Item 没有 `Question`，因此也没有 `questionId`。
- 连接器必须保留非题目 Item 的 `itemId`、位置和类型，不得伪造平台 `questionId`。如需统一内部 ID，只能明确标记为系统内部 ID。
- 普通题目的稳定题目键来自 `questionItem.question.questionId`。
- Grid 位于 `questionGroupItem`。其中 `questions[]` 的每一行都是独立 `Question`，每行都有各自的 `questionId` 和 `rowQuestion.title`。
- Grid 回答按每一行的 `questionId` 进入 `FormResponse.answers[questionId]`，不能只用题组的 `itemId` 或第一行题目 ID 代表全部行。
- 选项跳转来自 `Option.goToSectionId` 或 `Option.goToAction`；`goToSectionId` 指向目标 Section 的 `itemId`。
- Google `Option` 没有官方稳定选项 ID。选项身份必须由所属题目、快照版本、值和位置共同定位，并保留原始结构以处理同名与重排。

### 4.3 图片与 YouTube

- `Image.contentUri` 是输出字段，官方只保证有限时间内有效；它不能作为永久素材地址，不能写入长期日志或持久 fixture。
- `Image.sourceUri` 是输入字段，读取时可能为空，不能当作稳定回源地址。
- 真实样例的 4 个 `sourceUri` 全部缺失；两次紧邻 `forms.get` 之间 4 个 `contentUri` 全部变化，但对应下载字节哈希不变。
- 实测中取得 `contentUri` 后不携带 OAuth Bearer 仍能下载；因此该 URL 是短期敏感访问凭据，不得进入日志、错误正文、SSE、LLM 输入或持久存储。
- 高可信快照必须在授权读取后立即下载图片，校验重定向、MIME、文件签名、大小和超时，再计算内容哈希。
- 题干图、题组图、选项图和独立图片必须保留各自 JSON 路径与 Item/Question/Option 上下文，不能只按出现顺序绑定。
- `videoItem.video.youtubeUri` 只提供 YouTube 引用。Forms API 不返回视频字节、转录或可长期保存的视频快照，因此第 0～1 批只把它表达为外部引用，不宣称已经下载、转录或理解视频。

官方参考：[Google Forms `Form`、`Item`、`Question`、`Image`、`Video` 与发布状态定义](https://developers.google.com/workspace/forms/api/reference/rest/v1/forms)

### 4.4 回答关联

- `FormResponse.answers` 以 `questionId` 为键；普通题按题目 ID 关联，Grid 按行题目 ID 关联。
- 真实 OAuth 实测中，4 条回复共出现 23 个唯一答案键，与问卷的 23 个 `questionId` 完整闭合，没有无法映射的回答键。
- 停止收集后 `responses.list` 仍返回同样 4 条历史回复；恢复收集后计数不变。
- 回答原文不得进入仓库 fixture；只保存脱敏占位、计数和结构验证结果。

### 4.5 配额与重试边界

官方当前列出的读取配额为每项目每分钟 975 次、每用户每项目每分钟 390 次；`forms.responses.list` 属于昂贵读取，每项目每分钟 450 次、每用户每项目每分钟 180 次。连接器必须使用快照、缓存、幂等和有上限的截断指数退避处理 429，不能持续轮询或无限重试。

官方参考：[Google Forms API 使用限制](https://developers.google.com/workspace/forms/api/limits)

## 五、Google 问卷上传格式决策

Google Forms UI 的“导入问题”用于从另一份 Google Form 复用题目；官方没有提供可供本项目上传后无损恢复结构的通用原生问卷文件格式。PDF、截图、CSV 或普通 Excel 都不是 Google Forms 的官方结构化备份格式。

| 输入方式 | 可信等级 | 能保留什么 | 会丢失或不稳定的内容 | 决策 |
|---|---|---|---|---|
| Forms API JSON + 立即下载的图片快照 + 内容哈希 | 高 | Item/Question ID、题型、选项、Grid 行 ID、分页、跳转、素材位置、发布状态 | 产品获取需 OAuth；外部可行性已实测；`contentUri` 本身不能长期使用 | 后续 Google 连接器和备份包的目标格式 |
| PDF | 中 | 可见文字、可见顺序和页面视觉信息 | 稳定 ID、完整题型语义、隐藏分支、回答关联、可靠图片绑定 | 仅作为人工核对和降级解析输入 |
| 连续截图 | 低 | 截图中可见的文字与图片 | 完整题目集合、分页/跳转、隐藏内容、稳定 ID、回答关联 | 仅作低置信人工补充，不自动覆盖高可信结构 |

产品文案应称第一类为“Google Forms API 快照包”，不能称为 Google 官方原生导出文件。若用户只能提供 PDF 或截图，必须展示可信等级、缺失项和人工确认要求。

官方参考：[Google Forms 编辑与从另一表单导入问题](https://support.google.com/docs/answer/2839737)

## 六、倍市得验证与决策

### 6.1 原问卷 Excel：Go

项目现有倍市得原问卷 Excel 入口仍是稳定保底能力：

- 支持 `.xls` / `.xlsx` 原问卷；
- 可读取题号、题型、题干、选项和矩阵行；
- 可与“Excel-可读数据”回答列做确定性匹配；
- Provider 原始结构和 Canonical 结果可以同时保留；
- 该入口不依赖发布页在开放状态，也不要求在线连接器凭证。

因此“倍市得原问卷 Excel + 回答导出”判定为 **Go**，后续连接器不得移除或弱化该入口。

### 6.2 在线连接器：No-Go

倍市得公开开放平台页面能证明平台存在 API 对接能力入口，但本批没有取得以下生产证据：

- 可公开审计且覆盖问卷完整结构、图片、矩阵和跳转的正式 API 契约；
- 可用于非生产实测的正式授权方式和测试凭证；
- 问卷、题目、选项、页面和素材的稳定 ID 约定；
- 开放/停止收集下的一致返回行为；
- 自动化读取问卷内容和素材的许可、条款与公司合规确认。

因此倍市得在线连接器明确 **No-Go**。公开页、编辑页或动态请求即使能够被浏览器观察，也不得被包装成正式 API；不得通过抓页面、复用 Cookie 或逆向私有接口冒充生产连接器。

公开信息参考：[倍市得开放平台入口](https://www.xm-mysql.bestcem.com/openplatform)

## 七、Google Drive scope、权限与延期边界

### 7.1 最小 scope 决策

| 需求 | 候选 scope | 权限性质 | 当前决策 |
|---|---|---|---|
| 用户通过 Picker 明确选择并分享给本应用的文件 | `https://www.googleapis.com/auth/drive.file` | 按文件、非敏感，Google 官方优先推荐 | 第 3 批首选设计方向，仍需真实授权实测 |
| 只查看任意 Drive 文件元数据 | `https://www.googleapis.com/auth/drive.metadata.readonly` | 受限 scope；不能下载文件内容 | 不能满足素材下载，不作为单独解决方案 |
| 读取并下载用户可访问的全部 Drive 文件 | `https://www.googleapis.com/auth/drive.readonly` | 广泛、受限 scope，涉及额外验证和可能的安全评估 | 当前 No-Go；只有明确业务必要性和合规审批后再评估 |

Forms 的 `forms.body.readonly` / `forms.responses.readonly` 不包含 Drive 权限。不能因为 Forms API 返回了 Drive 文件引用，就假定连接器可以下载文件。

官方参考：[Google Drive API scope 选择](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

### 7.2 404 歧义

Drive 官方错误契约明确：`notFound` 404 既可能表示文件不存在，也可能表示当前授权用户没有读取权限。连接器不能仅凭 404 区分“已删除”和“无权限”，对用户应统一表达为“文件不存在或当前账号无权访问”，再提供人工核对、重新选择、上传副本或跳过。

Shared Drive 场景还可能要求 `supportsAllDrives=true`。未做 Shared Drive 实测前，不能把普通 My Drive 的结果外推到共享云端硬盘。

官方参考：[Google Drive API 错误处理](https://developers.google.com/workspace/drive/api/guides/handle-errors)

### 7.3 不自动发起访问申请

Google 官方用户界面支持在“需要访问权限”页面由用户点击申请，但 Drive REST API 没有面向无权调用者的“代用户发起访问申请”方法。`permissions.create` 是拥有相应管理权限的一方授予权限，不等价于无权限用户申请访问。

因此产品只能：

1. 提示用户在 Google 官方页面人工申请；
2. 等待授权后重试；
3. 让用户通过 Picker 重新选择已授权文件；
4. 上传合规副本；
5. 跳过该素材并继续主体分析。

官方参考：[Google Drive 帮助：申请文件访问权限](https://support.google.com/drive/answer/16722399)

### 7.4 第 3 批延期项

以下项目不在第 0～1 批实现，统一延期到第 3 批：

- 已授权 My Drive 文件的元数据与下载实测；
- 无权限与已删除文件的完整提示矩阵；
- Shared Drive 及 `supportsAllDrives`；
- Google Forms 文件上传题生成文件的归属和访问规则；
- token 加密存储、刷新、撤销和用户隔离；
- Picker 与 `drive.file` 的端到端流程；
- 公司合规、Google scope 验证与必要的安全评估。

在上述事项完成前，Google Drive 生产连接器为 **No-Go**。

## 十二、OAuth 部署配置清单

以下仅是后续实现建议，不代表当前已经修改 `.env` 或 `app/core/config.py`，也不包含任何 secret 值。

### 12.1 Google Cloud 与同意屏幕

- 建立独立的非生产和生产 Google Cloud 项目；
- 启用 Google Forms API；Drive API 仅在第 3 批授权验证启动时于对应测试项目中启用；
- 根据组织边界选择 Internal 或 External OAuth consent screen；
- 配置应用名称、支持邮箱、隐私政策、授权域名和测试用户；
- Web OAuth client 的 redirect URI 必须为精确 HTTPS allowlist，开发地址与生产地址分离；
- scope 分层申请：定义读取与回答读取按需请求，不预先申请 Drive 广泛权限；
- External 应用在上线前完成所需 Google 验证；若最终使用受限 Drive scope，先完成公司合规评估和 Google 要求的验证/安全评估。

### 12.2 建议配置变量名

| 建议变量名 | 用途 | 是否含敏感值 |
|---|---|---|
| `GOOGLE_OAUTH_CLIENT_ID` | OAuth Web Client 标识 | 否，但仍由部署配置管理 |
| `GOOGLE_OAUTH_CLIENT_SECRET` | OAuth Web Client secret | 是；不得写入代码、文档、日志或仓库 |
| `GOOGLE_OAUTH_REDIRECT_URI` | 精确回调地址 | 否；不同环境分别配置 |
| `GOOGLE_FORMS_BODY_SCOPES` | Forms 定义读取的按需 scope 集合 | 否 |
| `GOOGLE_FORMS_RESPONSE_SCOPES` | Forms 回复读取的按需 scope 集合 | 否；不需要回答时不申请 |
| `GOOGLE_DRIVE_READ_SCOPES` | 第 3 批经 Gate 确认后的 Drive scope | 否；当前不应启用广泛 scope |
| `GOOGLE_OAUTH_ALLOWED_DOMAINS` | 可选的企业域限制 | 否 |
| `GOOGLE_OAUTH_STATE_TTL_SECONDS` | 一次性 OAuth state 有效期 | 否 |
| `GOOGLE_OAUTH_TOKEN_ENCRYPTION_KEY` | refresh token 静态加密密钥 | 是；生成、轮换和托管方案需单独评审 |

这些名称只是候选；实际落地前必须按项目规则单独确认 `.env`、`.env.example` 与 `app/core/config.py` 的改动范围。

### 12.3 服务端安全与运维

- `state` 必须一次性、短时有效，并绑定平台用户、回调环境和发起会话；
- access/refresh token 必须按平台用户隔离，禁止跨用户复用；
- refresh token 必须加密持久化，密钥与密文分离；
- 支持撤销授权、解绑、刷新失败后重新授权和最小化 scope；
- 不在 URL、普通 JSON、SSE、异常正文、审计日志或 LLM 输入中记录 token；
- 日志只记录内部任务 ID、阶段、脱敏错误码和耗时；
- 回调、刷新和下载均需幂等、超时、重试上限和审计；
- 图片下载需校验重定向目标、MIME、文件签名、大小、超时和内容哈希；
- OAuth 与 token 存储实现属于部署和安全敏感改动，必须在后续批次单独确认。
