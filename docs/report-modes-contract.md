# 报告方式接入契约

## 已确认范围

入口选择 `report_mode=quick|insight|statistics`，分别为快速总结、观点洞察、统计解读。原有 `mode` 保留为数据引擎类型。兼容字段由服务端派生：quick 对应 report_focus=insight、report_style=quick；insight 对应 insight/full；statistics 对应 statistics/full。外部跑数表固定 statistics。

题目页默认显示全部题目，标签顺序为全部题目、主观题、待确认；所有有效题目初始全选。选择状态独立于 role=ignore。列确认提交完整 columns 与 selected_question_keys；question_key 为原始 column_indexes 升序用冒号连接（缺失时采用 column_index），例如 2 或 4:5:6。界面过滤不改变题目顺序或保存内容。切换报告方式不覆盖手工选择。

用户 ID 和 MLBB ID 默认放在主确认区，保留身份角色，不计入分析题数或 Q 序号。忽略字段和空白列默认折叠。

## 接口

- POST /api/analysis-settings/{session_id} 接受 report_mode（旧 report_focus 仍可读），返回解析后的模式与可用性。
- POST /api/columns/{session_id}/confirm 接受 columns 与 selected_question_keys；未提交选择列表的旧客户端默认全选有效题目。
- 快速总结确认题目和可选背景后直接 GET /api/report/{session_id}，不调用 plan 或 stats。
- 快速生成接口内部先执行确定性客观统计，再总结主观题；进度分别为 quick_statistics、quick_questions。允许仅选客观题，此时不调用模型。客观题按确认的选项映射、量程和矩阵定义计算总体分布，不展开画像交叉表。
- POST /api/plan/confirm 可提交 plan 对象以保存用户手工编辑的分析结构。
- POST /api/report/{session_id}/cancel 请求实际取消当前运行。
- POST /api/report/{session_id}/retry-failed 接受 base_version、可选 history_id，返回 SSE，仅重试该快速总结版本失败题目。历史会话过期时从所选历史版本冻结输入恢复临时会话。
- GET /api/report/{session_id}/sources?version=&question_key=&offset=0&limit=50&q= 返回当前指定版本的原文分页：items、total、offset、limit；items 含 response_id、text、question_key、question。
- 来源接口可用 history_id 查询历史报告，并执行历史所有权校验。
- 导出接口保留 version，新增 scope=body|evidence；默认 body，evidence 附加所选版本来源。

## 版本和执行状态

版本保存 report_mode、report_status=complete|partial、input_snapshot（题目定义、选择、背景、计划和来源指纹）、quick_summary（每题结果与完整来源），以及 quick_diagnostics。重生成继承所选基准版本；完整重生成全部执行并创建新版本，入口提前检查版本上限。失败重试只补全所选 partial 版本，版本号、创建时间、成功题目、冻结回答和全部画像保持不变，不占新版本名额；不受版本数量上限限制。成功题目缓存、冻结画像不完整或不兼容时明确停止，不静默执行全量或无画像重跑。保存前校验题目范围、成功内容、原文画像及引用，按 quick_completion_revision 拒绝旧结果覆盖新进度；历史作为补全的权威存储，单次原子写入指定版本，保留最新追问，累计用量和耗时，并在 quick_report_diagnostics.completion_attempts 留下各次记录。会话副本保存失败时，版本读取从历史恢复；旧会话回写不得覆盖更高补全修订。SSE report_done 返回 completion=true 和原版本号。前端在当前所选版本补全后刷新正文并保持阅读位置，查看其他版本时不强制切换。已有重试生成的旧版本不自动合并或删除。已完成版本的查看和导出不受管理员关闭快速入口影响。新生成须重新检查开关，不静默更换模式。

SSE 首先返回 session_ready，供历史恢复后的取消操作定位实际运行。取消会终止尚未完成的模型请求；已有成功题目、客观统计或已校验步骤时保存 partial 版本，未完成题目标记 cancelled，后续可从这些进度重试。完全没有可保存进度时不保存空报告。追问使用所选版本的冻结材料，即使当前题目定义或回答数据后来变化，也不替换旧版本依据。旧版本缺少冻结材料时不借用新版本的原文。

## 快速总结模型与流水线

执行器 `run_quick_pipeline(questions, *, background='', checkpoint=None, retry_failed=False, on_progress=None, on_checkpoint=None, collect=None)` 为纯异步编排；回调可为异步函数。输入题目为 `{question_key, question, sources:[{response_id,text}]}`，已经按原题顺序排列。返回 `{questions:[...], report_status, diagnostics}`；每题包含 question_key、question、status=complete|failed、findings、sources、error（可选）。findings 为 `{text,frequency,risk,evidence_ids}`；展示原文由服务端按输入 ID 回填。空有效回答题目无需模型调用。

每份输入完整进入单题批处理，包括已启用的选项 Other 原文。长回答分片保留同一 response_id 和偏移，不丢弃尾部。小题一轮，长题分批及题内合并，不跨题、不逐条精确归类、不执行全局写手。批次提炼与最终题目输出使用独立 schema；所有批次均处理不代表正文必须穷尽低价值观点。一般孤立观点允许省略，严重风险须保留并注明待核实。频次仅用反复提及、部分提及、零散提及、暂无法判断，不由引用数量或批次数推断。

全局并发默认 2，不再设置整份报告 600 秒或每题 240 秒的截止时间；旧配置仅用于验证旧版本缓存指纹。单次实际请求仍限 90 秒；每个提炼或合并步骤共享最多 3 次实际请求预算（含网络恢复、模型回退和结构修复），其中至多一次结构修复。客户端每次只发一个请求，临时错误或结构错误后由执行器选择下一个已配置模型；不能将预算全耗在同一故障模型，也不能让外层超时跳过回退。鉴权失败、拒绝及用户取消不自动重试。输入完整分批，每次请求不超过 18000 字符、输出上限 4096 tokens，最多 3 层中间合并；整轮合并不缩小时明确停止。因此工作量由完整输入、有限合并层数和每步尝试上限控制，不因排队时间耗尽整题预算。诊断分别记录题目排队、调用排队、模型执行、结构错误、步骤自动恢复原因和复用步骤；计划步骤数随合并分组更新。

checkpoint 同时保存成功整题和未完成题内已校验的原始批次、可用中间合并步骤。仅失败重试可复用，完整重生成忽略缓存。步骤按完整请求摘要定位，复用时重新校验结果摘要、结构、当前题目来源和风险覆盖；损坏步骤重新执行，不收敛轮次的合并缓存移除，原始批次保留。v6 可校验并继承 v3/v4/v5 成功整题（包括完整原文、画像、提示词、模型与预算），并复用 v5 已校验步骤；更老算法中间步骤不复用，旧版本数据不改写。

## 展示与洞察

快速报告按题目原序展示简短总结、粗略频次、必要风险及按需原文；部分失败明确显示，支持失败重试、完整重生成、取消、版本切换与正文/原文导出。观点洞察保留目标、精确统计和必要跨题分析；缩短总判断，同一发现只展开一次，行动含义放在相关发现处，不再重复章节总结和最终行动清单。统计解读保留原统计分析链路。

客观统计以 quick_summary.objective_stats 保存，包含 markdown、blocks、sections（question_key/question/source_order/markdown），同时冻结到 input_snapshot.objective_stats。报告按 source_order 将统计与主观总结交错展示；同一选择题的统计先于 Other 补充。历史重跑优先沿用所选版本冻结统计；旧版本缺少统计且没有原始表时明确说明需重新上传，不借用其他版本结果。客观精确计数不代表主观观点已做精确计数。

逐题状态与来源控件独立于正文挂载；同版本元数据刷新保留已有 quick_summary，切版后重新读取该版。按题提供精选证据和全部原文，失败题明确标为未完成。导出范围移入 PDF/Word/Markdown/飞书各格式的二级菜单，支持悬浮、点击和键盘，参数仍为 scope=body|evidence。

失败重试保留报告页、正文、目录、阅读位置和已打开的来源抽屉，运行状态独立于所选报告版本。紧凑进度条仅计算本次待重试题目，支持定位、详情及停止；顶部及滚动吸顶时保留 16px 间距。运行中禁止重复生成，后端补全与追问共用原报告的互斥锁。完成后，若仍在查看该版本，自动加载同一版本的补全内容并恢复阅读位置；查看其他版本时只提示“查看更新”。部分失败仍沿同一版本继续补全；冻结输入或缓存不完整时提供刷新入口，避免重复进入无法完成的重试。停止或连接错误仍保留当前正文。切报告后不将旧任务事件写入新报告的元数据；历史重试取消使用 session_ready 返回的运行会话。

模型输出允许规范化单个 JSON 代码围栏和 BOM；已确认合法的重复 evidence_id 按原序去重，不消耗修复调用。未知或跨题编号、无效频次等错误仍拒绝。合并输出仅缺少风险覆盖时，可从已校验上游候选完整补回缺失风险的原表述及引用，频次设为暂无法判断并标记待核实，再严格校验；不向无关观点硬塞风险编号。补回失败或存在其他错误时仍按每步一次结构修复及失败规则处理。诊断 structure_validation_errors 仅保存阶段、批号、固定错误类别和字段路径；JSON 解码错误另记录行列，不记录原文或模型输出。

质量代价：风险补回触发时必然增加待核实条目，可能产生重复或保留过度谨慎的上游判断；结构及来源校验不能证明模型语义准确。原始回答、画像和引用不截断，测试验证绑定完整性。速度代价：取消总截止后，慢请求较多时整份耗时可能超过原 600 秒；多个步骤格式失败时，每步一次修复会比原每题一次多调用。单步持久化必然增加保存次数与缓存体积，大样本时可能增加非模型耗时。复用成功步骤减少重读，但净耗时和真实模型质量仍需同规模实测，不能由模拟测试推出。

## 验证与风险

所有自动验证使用 .verification/report-modes 下隔离数据与缓存，不操作真实 data。契约测试须覆盖跳过旧规划/精确归类/全局写手、完整输入及尾批风险、引文 ID 校验、并发和超时、成功缓存与失败重试、取消、所选版本继承、管理员开关、来源/导出隔离、题目编辑序列化。

省去精确计数与跨题分析必然降低快速模式的定量精度和综合解释深度；粗略频次和省略零散观点可能漏掉普通长尾信息。洞察压缩可能损失细节，需实际报告验收。预计调用数量减少，但端到端中位数至少减少 50% 是同数据、同模型、同资源实测目标，尚未完成真实规模对照测试，不能声称已经达成。

冻结来源和题目检查点会增加版本存储、保存及传输的数据量；大样本或多版本时可能增加非模型阶段耗时，目前尚未实测量化。这部分开销须计入端到端速度验收，不能只比较模型调用次数。
